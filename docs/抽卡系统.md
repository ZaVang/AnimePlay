# 抽卡系统

> 本文基于实际代码（`config/gameConfig.ts`、`stores/gachaStore.ts`、`utils/gachaRotation.ts`）编写，取代旧的《抽卡机制》《README_CHARACTER_SYSTEM》《角色等级划分说明》三份已废弃文档。
> 动画卡池与角色卡池机制完全对称，下文以统一口径描述。

## 稀有度与概率

稀有度共 6 级，概率由**权重归一化**得出（`gachaStore.ts:40-71`），不是直接的百分比。

| 稀有度 | 权重 `p` | 实际概率 | 分解价值（知识点） |
|---|---|---|---|
| UR  | 0.5 | 0.83% | 200 |
| HR  | 2.5 | 4.17% | 100 |
| SSR | 7   | 11.67% | 50 |
| SR  | 20  | 33.33% | 25 |
| R   | 30  | 50.00% | 10 |
| N   | 0   | 0%（不参与常规抽取） | 3 |

- 有效总权重 = 0.5 + 2.5 + 7 + 20 + 30 = **60**；各档概率 = `p / 60`。
- **N 卡 `p=0`，正常抽卡抽不到**，仅在某稀有度池为空的兜底分支才可能出现（`gachaStore.ts:90-92`）。
- 数值来源：`gameConfig.ts` 的 `animeSystem.rarityConfig` / `characterSystem.rarityConfig`（两者数值相同）。

> 稀有度本身由**后端**按 Bangumi 人气分配（`backend/process_character_data.py`、`create_curated_dataset.py`），前端不计算稀有度，只消费已分级的卡数据。

## UP 池（限时轮换）

- 每个卡池每日轮换 **1 张 UR + 1 张 HR** 作为 UP 卡（`utils/gachaRotation.ts`，按日期确定性计算，每日 0 点切换，带多级缓存）。
- **UP 命中规则**（`gachaStore.ts:73-83`）：当本次抽卡 roll 到 UR 或 HR 稀有度时，有 **66%** 概率（`rateUp.hrChance = 0.66`）将结果替换为对应稀有度的 UP 卡。
- UP 池配置：`gameConfig.ts` 的 `rateUp.hrChance`。`rateUp.ids` 为空数组，运行时由轮换系统动态填充。

## 保底机制

两套独立保底，状态存在 `userStore` 的 `animePityState` / `characterPityState`（字段：`totalPulls`、`pullsSinceLastHR`）。

1. **UP 保底**（`gachaStore.ts:57-59`）：`pullsSinceLastHR` 达到 **70** 抽仍未获得 UP 卡时，第 70 抽**必定**给出 UP 卡。配置：`rateUp.pityPulls = 70`。
2. **十连保底**（`gachaStore.ts:105-112`）：单次抽卡数 ≥ **10** 且整组没有任何 SSR/HR/UR 时，将其中一张 N/R/SR 替换为随机 SSR。配置：`gacha.guaranteedSSR_Pulls = 10`。
3. **pity 重置时机**：抽到 UP 卡、或抽到 HR/UR 稀有度时，`pullsSinceLastHR` 归零。

## 商店（知识点兑换）

`components/gacha/GachaShop.vue` —— 三个页签：

- **今日 UP**：当前轮换的 UR / HR 卡，知识点直购。
- **历史 UP**：往期 UP 卡。
- **常规商品**：抽卡券、经验药水、知识点包等道具（`purchaseShopItem`）。

> ⚠️ **已知缺陷**：商品显示"每日限购: N"，但 `userStore.purchaseShopItem` / `purchaseFromShop` 没有任何限购计数，实际可无限购买（见审计报告一.3）。

## 抽卡流程（`GachaView.vue`）

1. 选择动画 / 角色卡池。
2. 卡池页：查看 UP Banner（含轮换倒计时、保底说明）、单抽 / 十连、概率一览弹窗。
3. 执行抽卡 → `gachaStore.performGachaLogic(type, count)` 返回结果（标 `isNew` / `isDuplicate`）→ `GachaResultModal` 展示 → 入库到 `userStore` 收藏 + 结算经验。

## 关键文件

- `config/gameConfig.ts` —— 概率/保底/分解/经验全部配置（**调平衡改这里**）
- `stores/gachaStore.ts` —— 抽卡核心逻辑（`performGachaLogic`）
- `utils/gachaRotation.ts` —— 每日 UP 轮换 + 缓存
- `stores/userStore.ts` —— 券/知识点钱包、pity 状态、收藏入库、商店购买
- `components/gacha/` —— `GachaView` / `UpBanner` / `GachaShop` / `GachaHistory` / `GachaResultModal` / `GachaRatesModal`

## 架构提示（重构相关）

抽卡 RNG 与保底状态全部在前端（`Math.random` + 客户端 `pityState` 回写存档）。单机自娱无碍；**若将来做排行榜/联机，这部分必须迁移到后端权威服务器**，否则结果可被篡改（详见审计报告第六节）。`gachaStore` 与 `userStore` 当前互相依赖（保底数据在 userStore、逻辑在 gachaStore），重构时建议将保底与抽卡历史一并并入 `gachaStore`。
