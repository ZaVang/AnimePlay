# Iteration 1 Plan — D5

## 待完成任务（按依赖顺序）
1. D5-T1: 基地 hub 统一主入口
   - 目标：让基地 hub 成为家园、角色、编队、探索、战斗五类体验的统一入口，玩家能在同一大类内完成核心循环。
   - 依赖：D1-D4 已完成，家园、养成、装备、5 人小队、挑战塔奖励与横板半自动战斗均已有可用基础。
   - 验收：基地 hub 中能清楚进入并切换家园、角色、编队、探索、战斗相关面板；玩家能从基地 hub 连贯完成“看家园 → 养角色/配装备 → 编队 → 探索爬塔 → 战斗结算”的路径。

2. D5-T2: 旧入口兼容与导航连续性
   - 目标：保留既有挑战塔与角色养成入口的可访问性，避免玩家通过旧导航或旧地址进入时遇到 404 或断裂体验。
   - 依赖：D5-T1。
   - 验收：旧挑战塔入口能到达基地 hub 的探索/挑战塔体验；旧角色养成入口能保留或到达基地 hub 的角色体验；现有导航不出现断链、死路或语义冲突。

3. D5-T3: 基地 hub 各面板信息完整性
   - 目标：让每个基地 hub 面板承担清晰的玩家决策信息，形成可理解的成长与战斗闭环。
   - 依赖：D5-T1、D5-T2。
   - 验收：家园面板保留角色走动与离线收益；角色面板展示五维、装备、养成、小队战技能；编队面板展示 5 人站位、战力、技能摘要；探索面板展示塔层、敌人、奖励预览；战斗与结算反馈能回流到角色成长、装备或资源变化。

4. D5-T4: 文档与现行机制一致
   - 目标：让挑战塔、角色养成和前端模块说明不再描述旧“前排轮流普攻”为现行规则，并准确反映基地 hub、横板半自动战斗、奖励与养成回流关系。
   - 依赖：D5-T1 至 D5-T3。
   - 验收：相关产品与前端说明文档中的入口、机制、奖励、养成和战斗表述与实际体验一致；旧规则只能作为历史背景或不再出现为当前主体验。

5. D5-T5: D5 验收闭环
   - 目标：证明基地 hub 整合可以作为 S13-D 收口阶段独立上线。
   - 依赖：D5-T1 至 D5-T4。
   - 验收：指定测试、类型检查、构建、engine/squad 纯度扫描全部通过；桌面与移动关键路径手动或截图验收通过；旧路由不 404；docs 与实际机制一致。

## 相关陷阱（从 pitfalls.md 筛选）
- [架构铁律] engine 必须保持纯净：不能引入 Vue/Pinia/DOM/fetch/localStorage/Math.random，上层展示和交互不能污染小队战运行时。
- [架构铁律] 依赖方向必须保持向下：视图、组件、状态编排只能消费下层能力，下层不能反向依赖视图或组件。
- [RNG] 随机源必须可注入：战斗、养成或奖励相关随机性不能直接调用 Math.random。
- [存档协议] 如需新增持久化字段，必须同步保证协议、迁移、装配与旧档往返保真；若只是设备级轻状态，不应误升存档协议。
- [养成重构] 当前养成只有等级与好感两轴；训练、活动、对话、礼物、心情不应作为现行机制回流。
- [装备系统] 实战战力、养成预览和装备加成口径必须一致，避免挑战塔表现与角色/装备页面显示不一致。
- [UI 颜色/令牌] 新 UI 应沿用项目语义色与现有主题约束，避免浅底白字、动态拼接颜色类或静默失效的 Tailwind 类。

```powershell
$pattern = 'Math\.random\(|localStorage|fetch\(|document\.|window\.|@/stores|@/views|@/components'
$scanOutput = rg -n --glob '*.ts' --glob '*.tsx' --glob '*.vue' $pattern 'frontend-vue/src/engine/squad'
if ($LASTEXITCODE -eq 0) { $scanOutput; exit 1 }
if ($LASTEXITCODE -eq 1) { 'engine/squad purity scan passed'; exit 0 }
exit $LASTEXITCODE
```
