## Executive Summary

**总评分：7.4 / 10**（上轮起点约 4/10 半成品 → 本轮切片已把「差异化」「可重复循环」两根断裂关节接上，工程质量高、验收全绿、无回归）。

- **功能体验（8/10）**：SA-T5 扫荡是干净的「止损补给」闭环——周上限防通胀、缩水+sqrt 边际递减杜绝「只扫最高层」Dead Zone、独立 action 不污染主线、跨周读时归零、回拨钳位。真正解决了「卡关即断更」。唯一体验盲点：**扫荡把经验发给谁，玩家在 UI 上看不到**（自动选「首个含成员小队」，飘字只报数值不报受益角色）。
- **审美品味（7/10）**：扫荡卡全语义令牌、进度条+飘字克制到位，不复用完整战斗演出面，符合「一键结算」定位。SA-T4 的差异化技能名（超电磁炮 / 时间停止 / 圆环之理）在角色面板 `selectedSkillRows` 里真实可见，名场面命名有口碑质感。**审美层最大遗憾：招牌 kit 与模板 kit 在 UI 上无任何视觉区分**——玩家看到「超电磁炮」却不知道它是手写签名 vs 隔壁的模板通名，收集 payoff 的「啊哈」被压在纯文本里。
- **产品想象力（7/10）**：SA-T4 的 10 条覆盖是机制层真差异（execute / revive / 群体 stun / 独特 DOT），不是倍率微调，判据「一眼说得出不一样」达标。但 `isSignatureKit` 已导出却零 UI 消费、`SignatureKitOverride.role` 已声明却零消费——两处「为未来留口」的前置数据，若下一轮不接线就会腐化成死字段。

**一句话**：本轮切片工程完成度极高、零回归，两根系统性根因（角色同质化、卡关断更）已实质缓解；refine 的重心不在「做得够不够深」（够了，且恰当地没过度），而在**把已经做出来的差异化「显形」给玩家看**——signature 徽章 + 扫荡受益角色可见，是把「代码里做了」变成「玩家感受到了」的临门一脚。

## Phase 1：功能体验

### 首次印象与上手路径
- 进 `/homestead?tab=explore`，扫荡卡落在探索面板已通层区，位置合理（探索=打塔的语义邻域）。文案分三态清晰：未通任何层→「先通过第 1 层」；可扫→「一键扫荡（剩 N 次）」；满额→「本周已达上限」。**新用户不读文档能懂**：进度条 + 「本周 N/M」+ 「缩水补给，不掉装备」一句把预期钉死，无误导。

### 核心流程逐步走查
1. **通第 1 层 → 扫荡资格解锁**：`sweepFloor = currentFloor - 1`，资格走 `hasCompletedFloor`，逻辑正确。
2. **点「一键扫荡」→ 飘字结算**：跳过 180ms 回放、`sweepFloat` 飘字 1800ms 后清、setTimeout 登记 + onUnmounted 清除——手感即时、无演出疲劳，符合「扫荡=补给非主 farm」定位。**这一步做得很对**：没有为省事复用 `SquadBattleResult` 完整面。
3. **周上限触顶 → 按钮禁用 + 「本周已达上限」**：明日方舟剿灭范式，免点击疲劳。
4. **跨周 → 额度归零**：`ensureThisSweepWeek` 读时判定、加载后立即判定、回拨钳位（周键相等即不重置）。跨天/周干净。

### 边界情况与错误处理
- 未登录：`canSweep` 含 `userStore.isLoggedIn` 门控，禁用态正确。
- 无有效小队：`sweepSquadId` 回落 `presetSquads[0]?.id ?? 1`，不崩。
- 脏档：migrations v15 类型守卫（`sweepWeekKey` 非 string / `sweepUsedThisWeek` 非 number → 回缺省），往返测试覆盖。

### 🟡 功能体验坑（本轮切片，SA-T5）
- **扫荡受益角色对玩家不可见**：`userStore.sweepFloor(floor, squadId)` 把经验发给 `pve.getSquadMembers(squadId)` 的实成员，但 UI 上 ①从不显示是哪个小队 ②飘字只报「知识点 +X · 经验 +Y」不报「谁 +Y」。玩家扫 10 次不知道练到了谁。而 `sweepSquadId` 自动选「首个含成员小队」——若玩家有多队，扫荡默默喂了他可能不想练的那队。**这是把一个本该有反馈的养成动作做成了黑盒。**（refine 见下）

## Phase 2：审美品味

### 配色与视觉层次
- 扫荡卡：`--c-surface-2` 底、`--c-accent` 进度条填充、`--c-highlight` 满额态、`--c-success` 飘字、`--c-ink/-2` 文字、`--c-line` 描边——**全语义令牌，零 text-white、零动态色类**，皮肤漫游安全。满额态用 highlight 色转移注意力，语义正确（绿=可领、highlight=已尽）。

### 字体与排版
- `summary-kicker`（小标签）→ h3 1.1rem 800 → hint .85rem，层级清晰有韵律。飘字 .9rem 800 success 色，克制。

### 间距与信息密度
- 扫荡卡是「标题行 + 进度条 + 一句预览 + 操作行」四段式，呼吸感够，不拥挤。进度条 8px 圆角 999px，细而不失存在感。

### 动效与过渡
- `sweep-float` transition：opacity + translateY 6px，进 .3s 出 .3s，自然。进度条 `width .3s ease`。动效增强理解（数值飘起=拿到了）、不喧宾夺主。

### 整体视觉性格与风格一致性
- 扫荡卡与探索面板其它卡片同构（summary-kicker 复用），一致性好。

### 🟢 审美坑（本轮切片，SA-T4）
- **招牌 kit 无视觉区分**：`selectedSkillRows`（角色面板技能列表）对签名角色和模板角色一视同仁渲染 `{name, desc}`。玩家抽到御坂美琴，技能面板确实显示「超电磁炮 / 单体高倍炮击+沉默」——**这是好的，差异化真的可见**。但隔壁一个模板 striker 显示「某某·斩击」，玩家无法一眼分辨「超电磁炮是精心手写的、斩击是模板凑的」。签名 kit 的 collection payoff 目前只能靠玩家自己读文本品出来，缺一个「专属」徽章把它抬起来。`isSignatureKit(characterId)` 正是为此导出——**但本轮零 UI 消费**。

## Phase 3：产品想象力

### 「如果能 XXX 就太好了」

1. 💡 **签名 kit 专属徽章 + 差异化技能高亮（SA-T4 收口，接线级）**：在角色面板 `selectedSkillRows` 对 `isSignatureKit(id)===true` 的角色，给签名的那一条 skill（skill1 或 ultimate）挂一个「★专属」小徽章 / 描边高亮。**素材全在了**（`isSignatureKit` 已导出、覆盖了哪一格 `SIGNATURE_KIT_OVERRIDES[id].skill1/ultimate` 已知），纯前端接线，一天内落地，直接把 SA-T4 的收集 payoff 从「藏在文本」抬到「一眼看见」。这是本轮切片投入产出比最高的一条。

2. 💡 **扫荡受益角色可见 + 可选（SA-T5 收口）**：扫荡卡加一行「本次经验将发给：小队 A（御坂/绫波/…）」缩略头像，飘字改「御坂 +55 · 绫波 +55」。进一步（可选）让扫荡沿用编队面板当前选中的 `selectedSquadId` 而非自动选首队，玩家换队即换练谁。把黑盒变透明。

3. 💡 **「本周扫荡剩余」提示前移到探索面板顶部 / 家园红点**：目前要滚到已通层区才看到「本周 N/M」。周上限是「限时福利」心智，值得像每日任务一样在 hub 层给个红点/角标，形成「每周回来领满」的回归钩子——SA-T5 的循环价值靠可见性放大。（**超范围**：红点系统已存在、接线成本低，但属 S14-B 留存范畴，标 backlog。）

### 可以删掉的东西
- 💡 **`SignatureKitOverride.role` 字段（若下一轮仍不接）**：该字段注释写「供未来 UI / SA-T3 头部映射消费」，但 SA-T3 已拍板走 base 五维比例、**明确不接此映射**；本轮也零消费。它现在是「文档性 role 声明」（人设倾向记录），有一定自文档价值，但**若 SA-T4 收口的徽章 UI 也不读它，它就是死字段**——要么接进徽章/定位展示，要么降级为纯注释。不建议无消费地长期留在类型里。

### 「啊哈时刻」分析
- SA-T4 的啊哈 =「我抽到的这个角色，在战斗里真的和别人不一样」。目前这个啊哈**来得太晚太弱**：要玩家进角色面板逐条读技能、或进战斗看施法，才隐约察觉。徽章 + 高亮能让啊哈在「点开角色卡」的瞬间就发生。
- SA-T5 的啊哈 =「卡关了也有事做、有产出」。这个啊哈已经落地得不错（扫荡按钮亮起+飘字），但「练到了谁」的不可见削弱了成就感。

## Phase 4：一致性与对比

### 跨视图一致性 / 回归复审（SA-T1..T5 全量）
- **SA-T1（编队编辑）**：`updateSquadMember/updateSquadName` 仍在、squad 面板可编辑，未被本轮改动波及。`deserialize` 仍做 `canonicalizeSquadMembers`（去重+5槽）。**无回归。**
- **SA-T2（敌人预览同源）**：SA-T4 覆盖是纯加法命中层，`filter(isSquadSkillKitReady)` 全角色集合天然不变（覆盖 kit 必过 `validateSquadSkillKit`），敌人候选池集合不变 → 种子同源未被破坏。测试有「覆盖前后集合不变」断言守着。**无回归。**
- **SA-T3（确定成长）**：本轮未碰 `nurture/rules.ts`。`SignatureKitOverride.role` 未被成长路径消费（SA-T3 走 base 比例），未污染。**无回归。**
- **SA-T4（差异化 kit）**：10 覆盖走 `skill()` 工厂 → description 自动派生（禁手写），命中覆盖/未命中回落原型，只用 9 种 squad effect、零引擎改、零 /battle effectId 泄漏。角色面板 `selectedSkillRows` 与探索预览 `skills` 均正确读覆盖后的名字。**「描述≠行为」红线守住。**
- **SA-T5（扫荡）**：`sweepFloor` 独立 action 绝不调 `completeFloor`；存档三处同改（schema v15 + migrations 类型守卫 + pve 装配器 `ensureThisSweepWeek`）+ 往返/脏档测试齐全。字段扁平定长（非 Record<floor,count>）。engine 纯净（`calculateSweepReward` 无 RNG/无 store import）。**无回归。**

### 与同类产品对比
- **扫荡 vs 明日方舟剿灭 / PCR 扫荡**：周上限 + 缩水 + 一键，范式对标准确，且比 PCR 更克制（不掉装备、边际递减），符合单机向定位——**没有过度堆循环，恰当**。
- **签名技能 vs PCR 专属技能**：PCR 每角色 4 条唯一技能且 UI 有专属图标/星级标记。本项目 10 条机制层差异是正确的第一步，但 PCR 的「专属感」有一半来自视觉标记——这正是本轮缺的徽章。

## Prioritized Recommendations

### 🔴 Critical（阻止发布）
- 无。本轮切片验收全绿、零回归、无功能缺陷。

### 🟡 Important（应尽快修）
- **[SA-T5] 扫荡受益角色不可见**：飘字/扫荡卡应显示经验发给了哪个小队/哪些角色（黑盒养成动作缺反馈）。最低成本：飘字改「角色名 +N」；进阶：卡内展示受益小队缩略。**验收卡点**：扫荡后 UI 能让玩家答出「刚才练到了谁」。
- **[SA-T4] 招牌 kit 与模板 kit 在角色面板零视觉区分**：`isSignatureKit` 已导出但零消费，签名 payoff 埋在纯文本。**验收卡点**：签名角色的技能面板有可辨识的「专属」标记，且标记只在 `isSignatureKit(id)===true` 时出现（false 角色不误标）。

### 🟢 Nice-to-have（锦上添花）
- **[SA-T4] 高亮「被覆盖的那一格」**：徽章落在具体被覆盖的 skill1/ultimate 上（数据 `SIGNATURE_KIT_OVERRIDES[id].skill1?/ultimate?` 已知哪格），比整卡打标更精准。
- **[SA-T5] `sweepFloat` 单 ref 快速连点会互相覆盖**：连点扫荡时前一条飘字被新值覆盖、看不出「领了两次」。可改为轻量队列或让飘字带 key 各自 transition。低危（周上限 10 次本就不鼓励狂点）。

### 💡 Feature Idea（backlog，不进本轮）
- **[SA-T5 收口 / S14-B]** 扫荡周额度红点前移到 hub 层，形成「每周回来领满」回归钩子（复用现有红点系统）。**超范围**（属留存 S14-B）。
- **[SA-T4 演化]** 长尾 base/rarity 分档（合同拍板⑥列为可选、有纯净风险则降 backlog）——若做必用角色自身 base 绝对锚点、严禁同原型均值。**超范围 / backlog。**
- **[清理]** `SignatureKitOverride.role` 若徽章 UI 仍不消费 → 接入定位展示或降级为纯注释，勿留无消费死字段。（标 SA-T4 收尾）

---

**收尾**：本轮切片（SA-T4+T5）在工程与产品双维度都是高完成度、恰到好处地「没过度」的一轮——扫荡不堆多循环、签名不扩全 66、engine 纯净存档三改齐全、零回归。真正的 refine 不是「再做深一点」，而是**把已做出的差异化显形**：signature 徽章 + 扫荡受益可见，两条接线级改动，就能把「代码里差异化了」兑现成「玩家一眼感受到差异化」——这才是 SA-T4/T5 收集向价值的最后一公里。
