## Executive Summary

**总评分：7.4 / 10**（较上轮 7.3 微升——SE-T1/SE-T3 两条轴已稳落地并有真手感；SE-T2 本轮尚未动工，评分反映「装备系统已有两条会长大的轴，但『搭配决策』这最后一块 build 拼图仍缺，按稀有度排序仍是最优解」）。

- **功能体验（7.5）**：装备现在有两条真实、可读的成长轴——SE-T1 强化（`●●●○○ Lv.3/5` + 下一级 delta + 「同款×1 + N KP」花费）与 SE-T3 modifier（暴击/增伤/治疗/护盾，经 View seam 真进战斗）。**唯一功能空白 = 玩家仍没有「搭配决策」**：`EquipPickerModal` 候选列表 `sort` 只按稀有度降序（`EquipPickerModal.vue:138`），玩家的最优策略永远是「戴能戴的最高稀有度那件」——P2-14「按稀有度排序即最优解」原样健在。SE-T2 是本 Sprint 唯一能把「戴哪件」从算术题（比数值）升级成决策题（凑套 vs 堆稀有）的机会。
- **审美品味（7.2）**：`EquipPickerModal` 的 delta 语言已经过两轮打磨、非常干净——「当前→新值(+Δ)」范式统一贯穿五维/战力/家园/强化四个分区，语义色（`text-success`/`text-danger`/`text-ink-3`）一致，`⚡` modifier 行有辨识度。**SE-T2 的审美风险在「套装进度无处显形」**：现在候选卡是「稀有度徽章 + 五维文案 + ⚡modifier + 家园」四行，套装信息若硬塞会撑爆信息密度；但若不显形，就是「有行为无描述」的隐性加成（CLAUDE.md 铁律反面）。必须给套装一套**克制的进度语言**（如「攻击套 2/3」小标签 + 齐套奖励一行），而不是无脑追加。
- **产品想象力（7.8）**：research-audit 的**替代 C（3 组取向套装：攻击/坦度/节奏，跨稀有度打 setId 标签，齐套奖 ≈ 半档稀有度）**是我见过对本项目「单机向、少而精」定位最贴的方案——它用**零新增装备、只给现有目录打标签**的成本，把「装备取向」概念立起来，天然对冲 P2-14（凑套需混稀有度 → 与堆最高稀有形成互斥取舍），还为未来「modifier 绑 slot 取向」铺路。这是把装备系统从「三条独立线性堆叠」升维成「有取向、有取舍的 build 系统」的临门一脚。

**一句话**：SE-T1（毕业曲线）+ SE-T3（战斗旋钮）已把装备的「纵向深度」做透，SE-T2 是唯一的「横向搭配深度」——它的成败不在工程量（走替代 C 是纯 store 闭环、零存档、零新依赖），而在**两个产品判断：① 走「3 组取向互斥套装」而非「每稀有度一套」，让凑套与堆稀有真正互斥；② 套装奖励是基于 def 原值/固定值的加法、绝不对强化后的值再乘、绝不塞 modifier（守住与 SE-T1/SE-T3 的正交）**。

## Phase 1: 功能体验

### 首次印象与上手路径（SE-T1 / SE-T3 回归复审 — 无回归）

两条已落地的轴复审下来手感扎实，无退化：

- **强化（SE-T1）目标感与反馈完整**：`●●●○○ Lv.3/5`（`enhancePips`）一眼看懂毕业进度；下一级五维 delta + 「同款燃料 N 件（拥有 M）」+ 「KP 成本（余 X）」三行同框，玩家能当场算「这一级值不值」；燃料/余额不足时按钮文案精确切换「燃料不足 / 知识点不足」，不灰一片让人猜；满级置灰「已强化到满级」有终点。**货币走 `profile.spend`、燃料吃游离同款件、装备中/自身不可当燃料（`freeFuelUids` 复用 `findEquippedBy` 守卫）**——经济与防呆都清白。
- **modifier（SE-T3）真进战斗且可读**：候选卡 `⚡ {{ modifierText }}` 用 `text-highlight` 语义色独立成行，与五维并列不打架；`resolveEquipModifiers` 三槽求和 + `MODIFIER_CAPS` clamp，且**绝不套 `enhancedBonus`**（modifier 恒定不随强化涨，两条 seam 干净分离）。这条边界钉得很死，是 SE-T2 该抄的作业。

### SE-T2 核心流程走查（功能视角的「该做多深才够」）

以「首次触碰套装」的玩家心路走一遍，逐步标注 SE-T2 必须提供的反馈锚点：

1. **「我怎么知道这件属于哪个套装？」** — 候选卡 / 背包卡必须显示 setId 归属标签（如「攻击套」）。**缺了这一步，套装系统对玩家完全隐形**，等于没做（研究报告 A5「有行为无描述」红线）。
2. **「我凑了几件了？」** — 配装弹窗右栏（或候选卡）必须显示当前该角色三槽内该套件数（如「攻击套 2/3」）。这是套装的**核心目标感来源**，等价于强化的 `●●●○○`。
3. **「凑齐了给什么？值不值？」** — 必须显示齐套阈值奖励（齐 2 件小奖 / 齐 3 件大奖的固定五维加法），且这个奖励要能进右栏「战力 当前→新值」delta——因为套装奖是纯五维加法，**天然能映射进 `calculateBattlePower`**（这点比 SE-T3 的 modifier 幸运得多，SE-T3 的乘区无法进战力 delta）。这是 SE-T2 UI 比 SE-T3 更容易做对的地方，务必利用。
4. **「凑套 vs 换更高稀有散件，哪个划算？」** — 这是 SE-T2 存在的**全部意义**。research A7 定了量级：**齐套奖 ≈ 提升半个稀有度档**。太大 → 套装变必选、散件无意义；太小 → 玩家无感、退回按稀有度排序。这条数值必须在 config 一处集中可调（类似 `EQUIPMENT_PRICES`），并有测试锁死量级。

### 边界情况与错误处理（SE-T2 特有，验收必须覆盖）

- **0 件 / 散装无套装**：`resolveEquipBonus` 输出必须与 SE-T2 前**逐字节一致**（套装计数全 < 阈值 → 额外加成全 0）。这是「不破坏单件求和」验收的直接体现，也是回归安全网——**建议保留一份 SE-T2 前的 `resolveEquipBonus` 快照测试**。
- **同 setId 同槽两件**：一个槽只戴一件，故同 setId 齐套必然「不同槽各一件」，计数天然 ≤ 3。填数纪律：**想要能齐 3 的套装，weapon/armor/supporter 三槽都要有成员**；只有 2 槽成员的套装最多齐 2。
- **顺序无关**：套装加成与逐件求和加法合并，纯加法天然满足顺序无关——但验收应显式断言（换槽顺序不改结果）。

## Phase 2: 审美品味

### 配色与视觉层次（无回归 + SE-T2 约束）

现有 `EquipPickerModal` 的语义色体系已经很成熟：稀有度渐变徽章（`rarityStyle().gradient`）、`text-highlight`（强化 +N / ⚡modifier）、`text-accent`（家园）、delta 的 `success/danger/ink-3` 三态。**SE-T2 套装标签必须复用这套令牌，绝不引入第 N 种色**。建议：套装归属用一个低饱和的 `bg-surface-2 + text-ink-2` 小 chip（中性、不与稀有度色打架），齐套触发态才点亮 `text-highlight`——「未齐=灰、齐套=亮」的二态语言与强化 pip 的 `●/○` 同构，玩家零学习成本。

### 间距与信息密度（本轮头号审美风险）

候选卡当前已是四行（名+强化角标 / 五维 / ⚡modifier / 家园），信息密度接近饱和。**SE-T2 若在候选卡再加「套装归属 + 齐套进度」两行，会撑爆**。建议分工：
- **候选卡**：只加**一枚套装归属 chip**（贴在稀有度徽章旁，如「攻击套」），不加进度——候选卡回答「这件属于哪套」。
- **右栏预览区**：新增一个「套装」分区（仿现有「装备强化」子区的分隔线 + 标题范式），显示「攻击套 2/3」进度 + 齐套奖励行 + 该奖励已计入上方战力 delta。右栏回答「凑了几件、齐套给什么」。

这样信息落位与「候选=选择、右栏=后果」的现有心智一致，不破坏呼吸感。

### 动效与过渡

SE-T2 无需新动效。但**齐套瞬间**（从 2/3 → 3/3）是一个天然的「啊哈时刻」爆点——若成本允许，齐套那一刻给套装 chip 一个 `text-highlight` 点亮 + 战力 delta 数字的既有 transition 就足够，不必新造粒子。克制即高级。

## Phase 3: 产品想象力

### 「如果能 XXX 就太好了」

1. **💡（本轮强烈建议采纳为落地形态）取向互斥的 3 组套装（research 替代 C）**：攻击套（偏 atk/sp）/ 坦度套（偏 hp/def）/ 节奏套（偏 spd/sp），跨 R..UR 各槽打 setId 标签。凑齐一套可能要混稀有度 → 与「堆最高稀有」形成真实互斥取舍。这是把 P2-14 连根拔起的最优解，且只需给现有目录打标签、不新增装备。**这不是超范围创意，这就是 SE-T2 应该采用的具体形态。**
2. **💡（backlog）套装可视化「图鉴」**：一个只读面板列出 3 组套装各自的成员与阶梯奖励，让玩家规划「我还差哪件」。本轮不做（SE-T2 只需配装弹窗内的进度显形即够），但收集向玩家会爱这个「凑套清单」。
3. **💡（backlog）齐套的风味台词 / 小图标**：如齐「攻击套」角色卡角标一枚 ⚔️。纯装饰、低成本、强化「我的 build 成型了」的成就感。本轮不做。

### 可以删掉的东西

- **SPRINT 里的 SE-T2「原型条件加成 / `resolveRole`」分支应当明确删除 / backlog**。`resolveRole` 全库不存在，条件加成需解析 archetype → 要么污染 equipment store 引入 gameData 依赖、要么改 `resolveEquipBonus` 签名波及 4 个消费点，测试成本陡增（要 mock 角色+技能+archetype 表），而 build 深度并不比套装高（research 对比表：B 方案「成本中高、深度中、引入耦合风险」全面劣于套装）。**本轮不开这个耦合口**——一旦开了，未来 SE-T3 若想「按 archetype 给 modifier」会沿用这条脏链路。条件加成 backlog 到「未来 archetype 解析接线做对时搭车」。

### 「啊哈时刻」分析

装备系统的三个「啊哈」现在是：拿到 UR（稀有度）→ 强化到满（SE-T1 毕业）→ **凑齐一套（SE-T2，本轮要造的那个）**。前两个已落地。SE-T2 的「啊哈」= **齐套那一刻战力跳一档 + 套装 chip 点亮**——它比强化更强，因为它是「我看懂了搭配、我主动做了取舍」的智力成就，而非「我氪够了资源」的堆叠成就。这正是收集向单机游戏最该给的正反馈。要让它来得**早**：低稀有度（R/SR）也该有可凑的套装，让新手在前期就尝到一次「凑套 > 单件」的甜头，而不是要等到 UR 才解锁搭配乐趣。

## Phase 4: 一致性与对比

### 跨系统一致性（SE-T2 必须对齐的既有范式）

- **与 SE-T1 强化对齐**：强化用 `●●●○○` 表进度、右栏子区展示 delta——套装应同构（「2/3」表进度、右栏子区展示齐套奖 delta）。玩家在同一弹窗学一次「进度+后果」语言，套装免费复用。
- **与 SE-T3 modifier 对齐**：modifier 钉死「不随强化涨、两条独立 seam」——套装必须同样钉死「**不随强化涨（基于 def 原值/固定值）、加法合并、绝不塞 modifier**」。三条轴各走各的 seam，注释与测试都要显式声明，防未来有人把它们乘起来。
- **单一战力口径铁律**：套装加成必须在 `resolveEquipBonus(charId)` 内、`sumStatBonus` 之后**加法追加**，绝不另拼第 N 套口径（与 SPRINT 铁律、SC 系 `resolveNurturedStatPoints` 单 seam 哲学一致）。

### 与同类产品对比

- **PCR（直接对标）**：无套装系统，装备是逐件 rank + 确定属性。SE-T2 让装备摸套装是**超出 PCR 口径的自由发挥** → 必须克制幅度，别让套装盖过 SC 系已投入的星级/好感养成主线（齐套 ≈ 半档稀有度是对的克制线）。
- **暗黑 / PoE（套装范式）**：可迁移「齐 2/4 阶梯触发」的凑套目标感；反面教训「套装配随机词条 → 无限刷」SPRINT 已拒绝，取「确定阶梯」即可。
- **杀戮尖塔（取向互斥）**：build 乐趣来自「选了暴击流就放弃续航流」——SE-T2 的 3 组取向套装正是这个思路的装备化，**互斥才产生决策，否则是伪深度**。这是本轮最该守住的产品意图。

## Prioritized Recommendations

### 🔴 Critical（阻止本轮切片验收 / 功能缺陷）

- **🔴-1｜SE-T2 必须真落地，不得降级为「回归确认」**（SE-T2）。本轮是第 3/3 收尾轮、SE-T2 是唯一指派切片，且工作树确认**尚未动工**（无 `setId`/`setBonusFor`）。前车之鉴 S14-A SA-T6、S14-B 暴击 UI 均因误判「新范围」被漏做——**本轮必须交付套装机制**，不是只跑回归。
- **🔴-2｜套装加成必须与强化正交（加法、非乘法）、绝不碰 modifier**（SE-T2）。加成基于 **def 原值或固定值**加法追加到 `sumStatBonus` 之后，**绝不对「强化后的值」再乘**（否则满级三件齐套 = 强化1.4 × 套装 → 双乘膨胀，hp 走 2.5 折算更夸张）；套装奖励**只能是五维加法，绝不塞 critRate/damageUp 等 modifier**（否则绕过 SE-T3 的双乘区 clamp 护栏直接叠爆暴击轴）。验收必须显式断言「套装加成不随强化放大」+「0 件时 `resolveEquipBonus` 与 SE-T2 前逐字节一致」。
- **🔴-3｜套装进度与奖励必须显形（有行为必有描述）**（SE-T2）。候选/背包显示 setId 归属 + 配装弹窗显示「齐几件 / 齐套奖励」，否则违反 CLAUDE.md「UI 宣称≠行为」铁律的反面「有行为无描述」。缺了显形，套装等于隐形，玩家算不明白 = 没做。

### 🟡 Important（体验问题，应在本轮做对）

- **🟡-1｜采用「3 组取向互斥套装」（research 替代 C）而非「每稀有度一套」**（SE-T2）。攻击/坦度/节奏三组跨稀有度打 setId 标签，凑套需混稀有度 → 与堆最高稀有形成真实互斥取舍，正面对冲 P2-14。工程最干净（纯 store 闭环、零存档、零新依赖）、数值集中可调（3 套改一处调全体）、填数只需给现有目录打标签。**这是「套装 vs 条件加成」抉择的正确落点。**
- **🟡-2｜齐套奖量级落在「≈ 提升半个稀有度档」并 config 集中可调 + 测试锁死**（SE-T2，research A7）。太大 → 套装必选、散件无意义；太小 → 玩家无感退回按稀有度排序。映射：setId → 阶梯奖 的表集中在 config 一处（类似 `EQUIPMENT_PRICES`）。
- **🟡-3｜信息密度分工：候选卡只加 setId chip，进度/奖励放右栏子区**（SE-T2）。候选卡已四行接近饱和，套装进度「2/3」+ 齐套奖 delta 放右栏（仿「装备强化」子区分隔线范式），复用现有 delta 语言，不无脑追加行、不另开弹窗（承接上轮 negotiation 🟡-2 信息密度红线）。

### 🟢 Nice-to-have（锦上添花）

- **🟢-1｜齐套瞬间套装 chip 点亮 + 战力 delta 既有 transition**（SE-T2）。把「2/3 → 3/3」做成一个克制的正反馈爆点，不新造粒子。
- **🟢-2｜低稀有度（R/SR）也铺可凑套装，让「啊哈」前移**（SE-T2）。新手前期就尝到「凑套 > 单件」的甜头，别让搭配乐趣锁在 UR 后。
