# AnimePlay 进化审计报告 · Round 3 / 3（收口轮）

> 角色：Product Evolution Reviewer（产品策略师）
> 日期：2026-06-16 · 分支：restructure
> 审计对象：动画宅的自我修养（AnimePlay）—— 基于 Bangumi 真实番剧/角色数据的单机网页抽卡 + 收集 + 多玩法游戏
> 方法：精读三轮已实装系统的当前源码（daily/codex/achievements 三 store + 三配置 + 三面板 + CodexPanel 定向解锁 + CardDetailModal 番剧资料区 + userStore 全部编排 + persistence schema v6 + 登录/加载流 isNewUser 路径）；`node` 实测 selected_anime 250 张 date/rating/rank 覆盖率（**100%**，年份跨 1993→2025、29 个不同年份）；WebSearch 三大收口主题竞品（mobile FTUE 2025 基准 / AniList·MAL Wrapped 传播文化 / Marvel Snap 赛季+周任务留存结构）。
> **本轮基线**：三轮已实装并提交——R1 留存引擎（每日任务+登录奖励 / 图鉴完成度+里程碑 / 18 成就 + 统一事件面）、R2 图鉴枢纽（定向解锁经济出口 N50~UR12000 / CardDetailModal 真实评分·排名·放送年）。**这些不再当缺失，只评估深度、找最后一块拼图。**

## Executive Summary

**产品进化成熟度评分：7.5 / 10**（R1 6.0 → R2 7.0 → R3 7.5）

三轮下来，AnimePlay 的"系统层"已经相当完整：动机引擎（daily/成就）装好了，价值枢纽（图鉴：既是知识点出口、又是真实数据舞台）也焊好了。R2 的定向解锁是漂亮的一笔——我在源码里确认它真的闭环了（`CodexPanel` 灰位可点 → `userStore.unlockCodexCard` → `spend` → `addCard` → 存档，定价 UR12000 守住了平衡）。**这是一个"骨架完整、零件扎实"的早期产品。**

但把它当成一个"第一次打开的人会怎么体验"来走，我看到一个刺眼的断层：**所有这些系统，新人感知不到，也没人引导他去用。** 三轮装了这么多齿轮，却没有一根"启动杆"把它们串成新人能感知的第一天。具体三个洞，正好对应本轮三个主题：

**① 首次体验 = 字面意义的零。** `isNewUser` 标志从后端一路送达 `loadFromServer`（`persistence.ts:157`），但**只用于初始化一份空存档**，之后再不被任何 UI 读取。新人登录后直接撞上：8 个一级导航 + 一个"今日任务"面板（4 条任务但没说先做哪条）+ 一句"欢迎新玩家"日志（会被后续日志淹没）。**首抽没有任何庆祝**（`drawCards` 只 `addLog`，UR 和 N 卡的"恭喜"只是一行文字）。空状态是死的——收藏 tab 是"找不到匹配的卡"，图鉴是"请先登录"。竞品基准（2025 FTUE）很残酷：onboarding 完成率行业均值仅 19%，做好了 Day1 留存能到 40-60%，做差了 <25%。**AnimePlay 现在是"做差了"那一档——不是因为引导烂，是因为根本没有。**

**② 留存只有最薄一层。** 每日任务 4 条，每条 target=1，**回访玩家 5 分钟做完就再无可做**。登录奖励是固定的（1 动画券+1 角色券），**不递增**。没有周任务（跨天追的目标）、没有登录连签日历（"别断"的损失厌恶钩子——这是手游公认最黏的回访机制，而 AnimePlay 连 `loginStreak` 这个字段都还不存在）。讽刺的是：代码里**藏着**一个"连续观看 7 天发券"（`viewing.ts:90`），但它绑在收看动作上、埋在 ViewingStats 组件里，没人当它是签到。**最强的留存钩子，恰恰是产品里最看不见的那个。**

**③ 差异化数据已铺好，但没收口成"传播素材"。** R2 让 250 张番剧卡的真实评分/排名/放送年第一次在 CardDetailModal 露出了（我实测 100% 覆盖、年份跨 1993→2025）。但这些数据停在"单卡详情"层——**没有任何一处把它们聚合成一张能截图、能发推、能炫耀的东西**。AniList Wrapped / MAL Wrapped 每年刷屏证明：anime 受众的核心传播行为就是"把我的收集/口味生成一张漂亮的卡发出去"。AnimePlay 握着同源真实数据，却差最后一道"聚合 + 出图"。

**最大进化机会，在 Phase 1（首次体验闭环）和 Phase 4（可分享成绩卡）的交叉点。** 前两轮在"系统深度"上投了两轮，**这最后一轮该投在"感知"上**——让新人第一天就被引导着摸到这些系统（onboarding），让老玩家有炫耀的出口把产品带出去（share card）。

一句话定位：**前两轮把发动机和油箱都造好了，这最后一轮要装的是"点火钥匙"（新人 onboarding，让引擎被感知）和"喇叭"（可分享成绩卡，让产品自己传播出去）。** 系统不缺了，缺的是让人"上手"和"安利"的临门两脚。

## Phase 1: 核心完整性

### 当前核心循环（三轮后）

```
登录 → 自动领登录奖励（固定 1+1 券，不递增）
     → 首页今日任务：抽1/赢1/收看1/养成1 → 领券+知识点（5分钟做完）
     → 玩 8 个玩法之一 → 统一事件面自动埋 markProgress + achievements.check
     → 收藏→图鉴：看 X/665 完成度，点灰位花知识点定向解锁缺卡（R2 新增，闭环）
     → 收藏→成就：看 N/18（被动累积，玩家不会专程来看）
     → CardDetailModal：看番剧真实评分/排名/放送年（R2 新增）
```

**闭环质量**：系统侧已经相当闭。R2 的定向解锁把"图鉴灰位"从死的变成了"花知识点能补"的目标——这是真正的进步，知识点终于有了配得上的去处。**但这个闭环对"新人"和"想安利的人"都是隐形的**：新人不知道这些系统存在，老玩家没有把成果带出产品的出口。

### 缺失的关键环节（按本轮收口价值排序）

1. **🔴 首次体验闭环完全缺失（本轮头号洞）。** 三个子问题，全部可在一个 onboarding 组件里收口：
   - **无引导**：`isNewUser`（`api.ts:11` → `persistence.ts:157`）现成且权威，但**从未驱动任何 UI**。新人面对 8 导航 + 4 任务，没有"先做这个"的下一步。FTUE 基准要求"time to first core action < 60s"——AnimePlay 现在新人摸到第一次抽卡的路径是自己瞎找。
   - **首抽无庆祝**：`drawCards` 抽到卡只 `addLog`（一行文字），**没有 confetti/sparkle 仪式感**。2025 FTUE 明确点名"首次奖励要庆祝"——这是新人"第一次爽"的关键节点，现在被浪费了。
   - **空状态全死**：收藏 anime/character 是"找不到匹配的卡"，无 CTA；图鉴/成就空状态只有"请先登录"。FTUE 要求空状态是"引导下一步"，不是"报告没有"。

2. **🟡 留存无纵深（回访 5 分钟即枯竭）。** 4 条单日任务做完即止；登录奖励固定不递增；**无周任务、无登录连签**。竞品（Marvel Snap 赛季 + 周任务、Clash Royale 递增签到）的共识是 daily + weekly + streak 三层叠加才是成熟形态。AnimePlay 只有最薄的 daily 一层，且这一层还没"今日全清打包奖励"。

3. **🟢 成就/图鉴/任务之间无导航红点串联。** 三个系统散在两个地方（首页 daily 面板 + 收藏的 codex/achievements tab），**互相不知道对方有可领奖励**。玩家达成了图鉴里程碑/成就，首页/导航没有任何红点提示"去收藏领奖"。系统建好了，但"有东西可领"这个信号没传到玩家眼前——这是三轮系统"信息没串起来"的最大毛刺。

### 空状态与边界（本轮复核）

- **图鉴空状态仍是亮点**：灰位剪影 + "🔓 X 知识点"角标（R2 加的），天然就是"还差这些 + 怎么补"的可视化。这是三轮里做得最好的空状态，可作为其他空状态的范本。
- **收藏/成就空状态仍死**：纯文字，无 CTA。onboarding 改造时应顺手给它们加"去抽卡 →"/"去玩法解锁 →"的 CTA。
- **首抽边界未利用**：新人第一次抽卡是情绪峰值，当前完全平淡处理。

## Phase 2: 竞争差距

### 竞品对比（聚焦本轮三收口主题）

**A. 首次体验 — 2025 Mobile FTUE 基准（直接可量化的差距）**

| FTUE 最佳实践（2025） | 行业基准 | AnimePlay 现状 |
|---|---|---|
| 引导式首个动作（learn by doing） | 顶级 app onboarding 完成率 40-50% | ❌ 无引导，新人自己找路 |
| time to first core action | 目标 < 60 秒 | ❌ 无人引导到"第一次抽卡" |
| 首次奖励庆祝（confetti/进度感） | Day1 留存 40-60% vs 无引导 <25% | ❌ 首抽只 addLog |
| 渐进式披露（一次教一个机制） | 避免新人被 8 导航淹没 | ❌ 8 导航全量铺开 |
| 空状态引导下一步 | 不是"报告没有" | ❌ "找不到匹配的卡" |

> **机会点**：这不是"竞品有花活我没有"，是"行业最低门槛我没踩到"。`isNewUser` 现成、统一事件面现成（"完成首抽"能直接监听）、daily/codex/解锁三个落点现成可指——onboarding 的所有素材都齐了，只差把它们串成一个 3-4 步的引导。

**B. 可分享成绩卡 — AniList Wrapped / MAL Wrapped（验证过的传播引擎）**

研究确认：MAL Wrapped、AniList Wrapped（due.moe / AniWrapped）每年刷屏，**核心是"把你的 list 数据变成可分享的 story 卡"**，纯浏览器本地生成、可截图发社媒。这是 anime 受众**已被教育成型**的传播心智。AnimePlay 的独特优势：它不是"你看过什么番"，而是**"你抽到/集齐了什么 + 这些番在 Bangumi 全站第几"**——一个收集成就维度的 Wrapped，竞品（看番工具）做不了"收集"，抽卡游戏（虚构 IP）做不了"真实评分坐标"。**AnimePlay 在这个交叉点上是独一份。**

**C. 留存纵深 — Marvel Snap 赛季 + 周任务结构**

Snap 的留存结构是 daily missions（习惯）+ weekly/season missions（跨天目标）+ 赛季感（月度更替的新鲜感）。AnimePlay 现在只有 daily，且 daily 还没做满（无全清奖励）。**最低成本的补法不是抄赛季，是补"周任务 + 登录连签"这两层**——复用现成 markProgress 事件面，周任务只是多遍历一张表。

### 本产品仍缺的"桌上赌注"（本轮）

1. **新人 onboarding**（FTUE 行业最低门槛，AnimePlay 未踩到）—— 本轮最该补。
2. **可分享成绩卡**（收集型 + anime 品类的传播标配，Wrapped 文化）—— 本轮差异化收口主菜。
3. **周任务 + 登录连签**（留存三层的后两层）—— 余量补。
4. **跨系统红点/可领提示**（手游通用，"有东西可领"的信号传达）。

## Phase 3: 功能深度

### 三轮系统深度复核

| 模块 | 当前深度 | 判断（本轮新视角） |
|---|---|---|
| 每日任务 | **浅** | 4 条单日 target=1，无周/无连签/无全清。R2 后未动，仍是一层 |
| 图鉴 | **中等→偏深**（R2 提升） | 完成度+灰位+里程碑+**定向解锁出口**（R2）做扎实了。仍只有稀有度一个维度，真实数据三矿（作品/年份/声优）只在单卡详情露出、未做收集分组 |
| 成就 | **中等偏浅** | 18 条覆盖 6 玩法，仍无进度可视化、无分类、计数会话级 |
| 经济出口 | **中等**（R2 修复） | 定向解锁闭环了，错位问题解决。深度 OK |
| 真实数据展示 | **浅但已破土**（R2） | 评分/排名/年份在 CardDetailModal 露出了，但停在单卡层，**未聚合成任何可视化/传播物** |
| **首次体验** | **零** | 三轮都没碰，是当前最浅的一环 |

### 可深化路径（复用三轮已建设施，边际成本低）

- **首次体验 → onboarding 闭环**：用现成 `isNewUser` 驱动一个引导组件（不进新存档，"已看过引导"用 localStorage 或一个布尔），监听统一事件面的"首抽完成"触发庆祝弹窗。**所有素材已在，只是组装。**
- **真实数据 → Wrapped 成绩卡**：codex completion 是纯派生（`codex.ts`），date/rating 已在前端（实测 100%）。成绩卡 = 派生这些数据 → Canvas/SVG 出图 → 下载。**零后端、零新存档、零联机。**
- **每日 → 任务体系**：`dailyTasks.ts` 加 `WEEKLY_TASKS`（累计 target），daily store 加按"周键"重置的 `weeklyProgress`，埋点 100% 复用现有 markProgress；登录连签加 `loginStreak`+`lastLoginDate`（lastLoginDate 已有半套）。需升 schema v6→v7。

### Power-user / 自定义（仍空缺，非本轮重点）

快捷键、批量、收藏高级排序/分组、卡组分享码、导入导出——仍为零。其中"收藏按放送年/评分排序"随 R2 数据暴露已半解锁（数据在前端了），可作为成绩卡的附带产出。

## Phase 4: 差异化与 Wow Factor

### "如果能 XXX 就太酷了"

**💡 Wow 1（本轮强烈推荐落地，传播引擎）：可分享的"图鉴 Wrapped 成绩卡"。**
前端 Canvas/SVG 一键生成一张炫耀图，聚合三轮已有的全部数据：
- **完成度**："图鉴 312/665 · UR 28/66"（codex 纯派生，现成）
- **收藏年表跨度**："你的番剧收藏跨越 1998 → 2024，最爱 2011 年（5 张）"（date 实测 100% 覆盖、29 个年份，现成）
- **品味坐标**："你收藏的番平均 Bangumi 评分 8.4 · 最高分藏品全站 #1"（rating_score/rating_rank 现成）
- **欧气/战绩**："本月抽到 UR ×3 · 对战胜率 ★★★★☆"
一键下载 PNG。**零后端、零联机、纯派生现有数据。** 这是 anime 圈最自然的口碑传播点——AniList/MAL Wrapped 每年验证。**也是把前两轮装的"图鉴完成度/真实评分"从"自己看的数字"变成"发出去的素材"的临门一脚。** 本轮差异化收口的主菜。

**💡 Wow 2（中件，复用 date）："我的番剧年表"时间轴。**
把拥有的动画卡按 `date` 铺成一条时间轴（1993→2025，29 年），每年一格显示拥有数/封面。"你的收藏从 1998 年的《XX》一路到 2024 年的《YY》"。**没有任何虚构 IP 的抽卡游戏能做这个**（它们没有真实放送年），是结构性护城河。比成绩卡重（要一个新视图），可作为成绩卡的"展开版"或下一步。

**💡 Wow 3（需后端，列 backlog）：按声优收集维度。**
"集齐花澤香菜配音的全部角色"是 anime 硬核圈最上头的维度。但声优数据藏在 `main_characters[].actors`，**被后端服务时剥离**（R2 已确认）——需后端吐"角色→声优"映射，非纯前端。三轮 evolution 都点过它、都因后端依赖搁置，**这是 S11/后端轮次最该捡起的差异化遗产**，不进本轮。

### 口碑传播点分析（本轮收口）

1. **晒 Wrapped 成绩卡**——收集型玩家核心炫耀欲，anime 圈被 Wrapped 文化教育成型的传播行为（Wow 1）。**本轮唯一能让产品"自己长出来"的功能。**
2. **"它认识我集的番，还告诉我全站第几 + 横跨多少年"**——真实数据聚合带来的"懂行 + 有坐标"感（Wow 1/2）。
3. **"终于把缺的那张 UR 用知识点补上了"**——R2 定向解锁的满足感分享（已实装的副产品）。

### 值得删掉或简化的东西（本轮）

- **🗑️ 简化"猜角色"为图鉴/每日挂件（三轮重申，本轮仍未做）。** 它仍占一个一级导航位，深度最浅（单模式+最高分），却让新人 onboarding 的"导航更复杂"。本轮做 onboarding 时，正好可以借机把它降级为图鉴里的"今日猜角色"小挂件——**既减一个新人要理解的导航项，又给每日任务多一个轻量入口**。若 onboarding 改造顺手可并；不强求。
- **🗑️ 警惕成绩卡过度堆砌（来自 Wrapped 反例）。** 做 Wow 1 时**克制信息量**——一张卡放 4-5 个最炫的数字（完成度/年表跨度/平均分/欧气）就够，别把 18 个成就全塞上。Wrapped 的传播力来自"一眼能晒"，不是"信息全"。

## Technical Health（附带简扫）

- **统一事件面仍是最大资产（三轮复用）**：`drawCards`/`battleFlow.endGame`/收看/养成/猜对/通层 6 处已并排调 `markProgress` + `achievements.check`。**周任务、onboarding 的"首抽完成"信号、都从这里挂，不改编排函数。**
- **onboarding 几乎零基础设施成本**：`isNewUser` 后端权威已送达（`persistence.ts:157` 现成判断点），首抽庆祝可监听 `drawCards` 返回（含 `isNew` 标记），"已看过引导"用一个布尔/localStorage 即可——**不一定需要升 schema**（若要随账号漫游则进 v7，否则 localStorage 足够）。
- **成绩卡 = 纯前端纯派生**：codex completion 已是 computed，date/rating 已在前端（实测 250 张 100% 覆盖 date/rating_score/rating_rank）。Canvas/SVG 出图无任何后端/存档/联机依赖。**这是本轮风险最低的功能。**
- **周任务/连签需升 schema v6→v7**：daily store 加 `weeklyProgress`（按周键重置）+ `loginStreak`/`lastLoginDate`（后者半套已有）。三处同改（schema/migrations/装配器）约定清晰，迁移补默认即可。**这是本轮唯一动存档的项**——故列 🟡 而非 🔴。
- **跨系统红点**：codex 有 `claimableMilestones`（现成 computed）、daily 有 `isComplete`、achievements 有 `isUnlocked`——**"有可领奖励"的信号源全部现成**，红点只是把它们聚到导航/首页一个 computed badge，零新存档。
- 测试 340 + lint + type-check 健在；S9 性能优化、S10 安全加固在位；成绩卡/年表复用 VirtualGrid 无瓶颈。
- **小债（顺手可清）**：CardDetailModal 的卡类型仍 `[key:string]:any` 兜底（R2 已注意），做年表/成绩卡读 date/rating 时可顺手补 `AnimeCard` 的可选字段类型。

## Prioritized Recommendations

> 面向 Planner：本产品是**单机网页抽卡游戏**，以下全部"单机即成立、一个 Vue 视图/组件 +（可选）一个 store 可交付"。**"基于玩法事件"的项复用三轮已建的 markProgress/check 统一事件面，不改编排函数。** 工作量按"一轮 product-loop 能否做完"标注，并注明是否动存档。

### 🔴 Critical（本轮头号洞，阻止新人留下来）

**🔴-1. 新人 onboarding 闭环（首次体验）—— 把三轮装的系统串成新人能感知的"第一天"**
- 做什么：用现成 `isNewUser` 驱动一个 onboarding 组件，三件事一起做：
  ① **3-4 步遮罩引导**（渐进披露）：「这是今日任务，做完领券 →」「这是图鉴，灰位能花知识点补缺卡 →」「去抽第一张卡 →」——每步指向一个已落地系统的明确下一步。
  ② **首抽庆祝**：监听 `drawCards`（含 `isNew` 标记）→ 首次抽卡弹 confetti/sparkle 庆祝弹窗（2025 FTUE 明确点名的情绪峰值）。
  ③ **空状态加 CTA**：收藏/成就空状态从死文字改为「去抽卡 →」「玩对战解锁 →」。
- 为什么：**本轮最高优先。** FTUE 基准残酷——无引导 Day1 留存 <25%，有引导 40-60%。三轮装了这么多系统，新人却感知不到任何一个。所有素材（isNewUser / 统一事件面 / daily·codex·解锁三个落点）全现成，这是"组装"不是"从零造"。
- 工作量：**半轮~一轮**。**不一定动存档**（"已看过引导"用 localStorage 即可；若要随账号漫游再进 v7）。改动集中在一个 OnboardingOverlay 组件 + drawCards 庆祝钩子 + 几处空状态文案。
- ⚠️ 守住：渐进披露，一次只指一个下一步，别把 8 导航一次性灌给新人；提供 skip。

### 🟡 Important（显著提升完整度 + 传播力）

**🟡-2. 可分享的"图鉴 Wrapped 成绩卡"（差异化收口 + 口碑传播引擎）**
- 做什么：一个"生成成绩卡"按钮（放收藏/图鉴页或首页），Canvas/SVG 聚合现有数据出一张炫耀图：图鉴完成度（X/665 · UR n/m）+ 收藏年表跨度（1998→2024 · 最爱 XXXX 年）+ 品味坐标（平均 Bangumi 评分 · 最高分藏品全站排名）+ 本月欧气/战绩，一键下载 PNG。
- 为什么：**本轮差异化主菜，也是唯一能让产品"自己传播出去"的功能。** AniList/MAL Wrapped 每年验证 anime 圈传播力；AnimePlay 在"收集成就 × 真实评分坐标"的交叉点上独一份。把前两轮的"图鉴完成度/真实评分"从自己看的数字变成发得出去的素材。
- 工作量：**半轮~一轮**。**零后端、零存档、零联机、纯派生**（实测 date/rating 100% 覆盖）。本轮风险最低、传播 ROI 最高的功能。改动集中在一个 ShareCard 组件（数据派生 + Canvas 绘制 + 下载）。
- ⚠️ 守住：克制信息量，一张卡 4-5 个最炫数字，"一眼能晒"优先于"信息全"。

**🟡-3. 周任务 + 登录连签递增日历（留存三层的后两层）**
- 做什么：① `dailyTasks.ts` 加 `WEEKLY_TASKS`（累计型，如"本周赢 10 场""本周收看 20 次"），daily store 加按周键重置的 `weeklyProgress`——埋点 100% 复用现有 markProgress。② 登录奖励改递增连签日历（`loginStreak`+`lastLoginDate`，断签归零，7 天循环递增），用损失厌恶驱动回访。③（顺手）daily 加"今日全清"打包奖励。
- 为什么：当前回访 5 分钟枯竭；竞品（Snap 周任务 / Clash 递增签到）证明 daily+weekly+streak 三层才是成熟形态，连签的"别断"比固定奖励更黏。**注**：代码里已埋的"连续观看 7 天发券"（`viewing.ts:90`）可借这次机会提到登录连签日历里被玩家看见。
- 工作量：**一轮**。**唯一动存档的项**（升 v6→v7，三处同改 + 迁移补默认）。逻辑与现有 daily 同构。

### 🟢 Nice-to-have（体验打磨 / 把系统串起来）

**🟢-4. 跨系统"可领奖励"红点提示**
- 做什么：导航/首页加一个 computed badge——当 codex 有 `claimableMilestones`、daily 有未领完成任务、achievements 新解锁时，对应导航项/收藏 tab 显示红点。
- 为什么：三轮系统散在两处、互不通信，玩家达成了奖励却不知道去领。信号源（claimableMilestones / isComplete / isUnlocked）全现成，红点只是聚合。这是把三轮系统"信息串起来"的最低成本毛刺修复。
- 工作量：**半轮**。零新存档（全派生现成 getter）。

**🟢-5. 收藏按真实维度排序/分组 + "我的番剧年表"时间轴**
- 做什么：① 收藏加按"放送年/评分/拥有数"排序（数据 R2 已暴露，顺手）。② 图鉴加"年表"视图：拥有动画按 date 铺时间轴。
- 为什么：年表是结构性护城河（虚构 IP 抽卡游戏做不到），也是成绩卡 Wow 1 的"展开版"。可作为 🟡-2 的延伸。
- 工作量：**半轮**（排序）~**一轮**（年表视图）。纯派生零后端。

### 💡 Feature Idea（差异化创新，放 backlog）

- **💡-6. 按声优收集维度**：「集齐花澤香菜配音的全部角色」图鉴+里程碑。anime 硬核圈成瘾点、竞品物理做不到。**⚠️ 需后端吐"角色→声优"映射（main_characters 被剥离）**，三轮 evolution 都因后端依赖搁置——**S11/后端轮次最该捡起的差异化遗产**。
- **💡-7. 卡组分享码 / 导入 Bangumi 看过列表**：单机异步分享 + 工具用户转化。远期高粘性，需后端配合。
- **💡-8. 成就进度可视化 + 分类**：18 条加 category + 进度条（"7/10"）。R2 已评估，因计数需持久化有真实成本，本轮让位给更高 ROI 的 onboarding/成绩卡，留 backlog。

### 给 Planner 的一句话结论（收口轮）

**本轮（最后一轮）最高 ROI 的组合是 🔴-1（新人 onboarding）+ 🟡-2（可分享 Wrapped 成绩卡）——前者是"点火钥匙"（让新人第一天就被引导着摸到三轮装的所有系统，踩中 FTUE 行业最低门槛），后者是"喇叭"（把图鉴完成度/真实评分聚合成一张能截图安利的炫耀卡，让产品自己传播出去）。两者都零后端、几乎不动存档（onboarding 用 localStorage、成绩卡纯派生）、各半轮可交付，一个 Sprint 内能一并落地。** 它一头一尾地补齐了产品最后两块拼图：让人**愿意上手**（onboarding）和让人**愿意安利**（share card）。前两轮在"系统深度"上投了两轮、把图鉴打造成了价值枢纽；这最后一轮就该投在"感知与传播"上——系统已经不缺了，缺的正是让它被新人感知、被老玩家带出去的临门两脚。若还有余量，再叠 🟡-3（周任务+连签）补留存纵深、🟢-4（红点）把三轮系统串起来。
