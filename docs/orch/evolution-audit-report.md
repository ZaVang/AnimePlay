# AnimePlay 进化审计报告 · Round 1 / 3

> 角色：Product Evolution Reviewer（产品策略师）
> 日期：2026-06-16 · 分支：restructure
> 审计对象：动画宅的自我修养（AnimePlay）—— 基于 Bangumi 真实番剧/角色数据的单机网页抽卡 + 收集 + 多玩法游戏
> 方法：精读 8 视图 + 全部领域 store + 持久化 schema + 配置 + 真实数据样本；WebSearch 研究 6 类竞品（AniList/MAL、Genshin/FGO、Marvel Snap/Hearthstone、Pokédex、NTE 羁绊）。

---

## Executive Summary

**产品进化成熟度评分：6.0 / 10**

AnimePlay 已经远超"demo"。它有 8 个真实现的模块、305+ 测试、性能优化过的首屏、账号鉴权、5 套皮肤、66 位 UR 各 2 个真生效技能——**工程地基与玩法广度都是"早期产品"水准**，不是原型。问题不在"能不能玩"，而在"为什么明天还要再打开"。

当前的核心循环是**离散的、无引力的**：抽卡→收集→（对战 / 爬塔 / 养成 / 猜角色）四条玩法各自独立，彼此几乎不反哺，且**没有任何把玩家拉回来的钩子**——没有 onboarding 告诉新人该干什么，没有每日重置发糖，没有成就，没有图鉴完成度，没有让 665 张卡"集齐"成为目标的机制。玩家第一次登录会看到一个塞满抽卡券的界面，抽几十发，然后……没有下一步指引。这是一个"内容很多但没有动机线"的产品。

**最大进化机会在"核心完整性"维度（Phase 1）**：这个产品缺的不是更多玩法，而是**把现有玩法串成一条"每天回来→有事可做→有进度可看→有目标可追"的留存主线**。其次是把它**唯一无法被任何竞品复制的资产——Bangumi 真实番剧元数据（真实评分/真实放送年份/真实声优）**——从后台 JSON 变成玩家能感知、能玩、能炫耀的东西（Phase 4 差异化）。

一句话定位：**它是一个"玩法齐全但没有动机引擎"的早期产品，本轮最该装上的是动机引擎（每日循环 + 成就/图鉴），而不是第 9 个玩法。**

## Phase 1: 核心完整性

### 当前核心循环分析

实际能做的（已验证，均真实现）：

| 环节 | 现状 | 闭环？ |
|---|---|---|
| 抽卡 | 动画/角色双池、UP 每日 0 点轮换、70 抽保底、十连保底 SSR、商店每日限购、一键分解重复卡 | ✅ 完整 |
| 收集 | 665 角色 + 动画卡，按名称/稀有度/标签筛选、虚拟化大列表、卡组构筑（30 动画 + 4 角色） | ✅ 但只能"看"，无目标 |
| 宅理论战 | 完整卡牌辩论对战 + 结算面板 + 经验/知识点奖励入账 | ✅ 闭环（S6 修） |
| 挑战塔 | 小队逐层数值战、塔进度持久化、最高 999 层 | ✅ 闭环 |
| 养成 | 好感/角色等级/属性/战斗强化/对话/训练冷却，反哺小队战 | ⚠️ 数值闭环，但无情感/目标钩子 |
| 猜角色 | 像素化猜角色、稀有度加权、最高分持久化 | ✅ 闭环 |
| 观看队列 | 3 槽位、按稀有度定时（10min~4h）、收取给经验+知识点、**7 天连续观看奖券**（埋得很深） | ✅ 唯一的"回访"钩子，但不可见 |

**关键诊断：四条玩法之间几乎不互相喂养。**抽到的卡可以拿去对战/养成/爬塔，但反过来——对战赢了不会推进收集目标，爬塔通关不解锁新卡池，养成满级不喂养对战之外的任何东西。玩家在每个玩法里是"孤岛式"前进的，没有一条贯穿全局的进度主线把"今天我该干什么"回答清楚。

### 缺失的关键环节（按影响排序）

1. **🔴 完全没有 onboarding / 新手引导。** `App.vue` 登录后直接 `RouterView`，PlayerStatus 显示一堆数字，新用户拿着 100+100 张券面对 8 个导航项，零指引。第一次抽卡没有"恭喜你抽到第一张 UR"的庆祝引导，没有"试试用它去对战"的下一步。`NurtureView.vue:51` 自己挂着 `TODO: 实现更多交互功能`，`NurtureActions.vue:687` 挂着 `成就系统` 占位注释——团队知道缺，但没做。

2. **🔴 没有每日回访循环。** 全仓搜索 `签到/每日任务/dailyTask/login bonus` 零命中。唯一的每日机制是商店限购计数（`shop.ts`）和 UP 池轮换（`rotation.ts`）和那个埋在 `viewing.ts:90` 里、要求连续 7 天观看才触发一次的奖券。**没有"今天登录领 X 券"、没有"今日任务：抽卡 1 次 / 赢 1 场对战 / 看完 1 部番"、没有每日重置的目标列表。**这是单机抽卡游戏留存的头号引擎，完全空缺。

3. **🔴 665 张卡没有"图鉴完成度"。** `CollectionsView` 只展示"我拥有的"卡，没有"全卡池 X/665、UR 12/66"的进度，没有未拥有卡的灰色占位（玩家不知道还差哪些、不知道自己离集齐多远），没有任何"集齐 N 张 / 集齐某动画全角色"的里程碑奖励。收集型游戏最核心的成瘾点——补全欲——被白白浪费了。

4. **🟡 没有成就系统。** 抽到第一张 UR、集齐某稀有度、爬塔到 50 层、养成满级、猜角色连对 10 次——这些天然的"高光时刻"没有任何记录、徽章或奖励。

5. **🟡 知识点几乎没有消耗出口（经济失衡）。** `profile.earn('knowledgePoints')` 在观看、对战、升级处大量产出，但翻遍 `shop.ts`（用券购买）和各玩法，**知识点几乎只进不出**。一个只涨不花的货币等于没有货币，玩家攒到几万也无感。缺一个知识点商城/兑换出口。

6. **🟡 没有全局通知/提醒。** 观看队列何时看完？训练冷却何时好？UP 池换了没？玩家只能自己点进各页面查。导航栏没有任何红点/角标提示"这里有东西可领"。

### 空状态与边界情况覆盖

- **空状态偏弱但不缺失**：`CollectionsView`/`NurtureView` 未登录有文案提示；筛选无结果有"找不到匹配的卡"。但都是**纯文字的死状态**，没有引导性 CTA（例如收藏为空时应有"去抽第一张卡 →"按钮）。
- **错误状态合格**：`App.vue` 数据加载失败有 😵 重试面板；抽卡有错误条 + 清除按钮；这部分 S9 做得不错。
- **移动端明确放弃**：`App.vue:47` 顶部一条"建议用电脑访问"提示，桌面优先是已记录的 S7 决策（移动重排推迟到 S11），本轮不算缺陷，但限制了传播面（手机刷到链接的人进不来）。

## Phase 2: 竞争差距

### 竞品功能对比

研究了三类竞品（每类用户群与 AnimePlay 高度重叠）：

**A. 抽卡手游元系统（Genshin Impact / FGO）**

| 标配功能 | Genshin/FGO | AnimePlay |
|---|---|---|
| 每日委托 / 每日任务（4AM 重置，做满给premium货币） | ✅ 核心 | ❌ 无 |
| 每日登录奖励 / 周期登录活动 | ✅ | ❌ 无 |
| 三段式回访循环（3h/6h/每日体力或委托） | ✅ | ❌ 无 |
| 限时活动（赛季/版本） | ✅ | ❌ 无（UP 轮换算半个） |
| 任务/成就给奖励 | ✅ | ❌ 无 |

> 用户反馈机会点：Genshin 玩家公认"每日委托 60 原石"是雷打不动的回访理由——**一个轻量、做得完、给得起的每日清单就足以建立日活习惯**。AnimePlay 有充足的券/知识点可发，缺的只是这个"每日清单"容器。

**B. 动画收集/追番工具（AniList / MyAnimeList / Kitsu）**

| 用户称赞的功能 | AniList/MAL | AnimePlay |
|---|---|---|
| 漂亮的统计页（看过多少、类型分布、年份分布） | ✅ 用户高频称赞 | ⚠️ 有 `ViewingStats` 但极简 |
| 新番放送日历 / "新一集上线提醒" | ✅ 最受欢迎功能之一 | ❌ 无（但有 `date` 数据！） |
| 真实评分/排名展示 | ✅ | ❌ 数据里有 `rating_score/rating_rank` 但游戏里不显示 |
| 收藏可分享/可炫耀的 profile | ✅ | ❌ 无 |

> 机会点：AnimePlay 的卡 = 真实番剧，已经握着 AniList/MAL 同源的数据（`date`/`rating_score`/`synergy_tags`），却**只把它们当成抽卡奖品，没当成"追番工具"来用**。这是横跨"游戏"和"工具"两个用户群的差异化富矿。

**C. 卡牌对战游戏（Marvel Snap / Hearthstone）**

| 标配功能 | Snap/HS | AnimePlay |
|---|---|---|
| 卡组分享码（一串字符导入整套牌） | ✅ 社区刚需 | ❌ 无 |
| 收集进度路（Collection Level Road，集卡推进解锁） | ✅ Snap 核心进度轴 | ❌ 无 |
| 单人/每日任务给卡或货币 | ✅ | ❌ 无 |
| 卡组多套预设 + 命名 | ✅ | ✅ 已有（对战卡组 + 小队预设） |

> 机会点：**卡组分享码**是几乎零依赖（一个编解码函数 + 复制/粘贴 UI）就能做出的口碑功能，且为 S12 多人时代提前铺路。

### 本产品缺少的"桌上赌注"（table stakes）汇总

1. 每日任务 + 每日登录奖励（三类竞品都有）
2. 成就系统（手游 + 卡牌都有）
3. 图鉴/收集完成度进度轴（Snap、Pokédex、收集类通用）
4. 卡组分享码（卡牌品类刚需）
5. 真实评分/放送信息展示（追番工具刚需，且 AnimePlay 数据现成）

## Phase 3: 功能深度

### 现有功能深度评估

| 模块 | 深度 | 判断 |
|---|---|---|
| 抽卡 | **有深度** | 双池 + UP 轮换 + 双层保底 + 商店 + 分解，机制完整，是全产品做得最扎实的部分 |
| 宅理论战 | **有深度** | 132 技能真生效、结算奖励、AI 对手画像，机制密度高 |
| 收集 | **浅** | 只有"看 + 筛选 + 分解"，无完成度、无排序维度（只能稀有度+名称）、无标记/收藏夹分组、无对比 |
| 养成 | **中等偏浅** | 数值系统完整，但情感层为零：好感度无上限却不解锁任何东西，对话是静态的，无羁绊等级、无角色故事、无 CG/语音解锁 |
| 猜角色 | **浅** | 单一模式（像素还原），只有最高分，无每日挑战、无连胜、无排行、无"猜声优/猜番剧"变体 |
| 观看队列 | **中等** | 定时 + 稀有度奖励 + 连续天数，但只有 3 槽、奖励不可视化、连续奖励埋太深 |

### Power-user 路径（当前几乎为零）

- ❌ 无快捷键（抽卡、跳过对战动画、确认弹窗都得点）
- ❌ 无批量操作（除了"一键分解重复卡"，没有批量收藏/批量加入观看队列）
- ❌ 无高级排序/分组（收藏不能按"放送年份/评分/拥有数量/养成等级"排，不能按动画分组看角色）
- ❌ 无导入导出（存档不能导出 JSON 备份/分享；卡组不能导出码）
- ❌ 无搜索增强（不能搜"我还没拥有的 UR"、不能按声优搜角色）

### 集成 / 协作 / 自定义可能

- **自定义**：有皮肤（5 套），但仅此而已。无法自定义主页布局、无法设置常用卡组为"主力"、无个人签名/头像（可用拥有的角色卡当头像——零成本高情感）。
- **集成**：数据源是 Bangumi，**天然可做"一键导入我的 Bangumi 看过列表 → 自动点亮对应卡"**（远期但极具粘性，把追番工具用户直接转化为玩家）。
- **协作/分享**：单机阶段最现实的是**异步分享**——分享卡组码、分享"我的图鉴完成度截图卡"、分享猜角色成绩，全部不依赖联机。

## Phase 4: 差异化与 Wow Factor

### "如果能 XXX 就太酷了"（不受 Sprint 限制）

**💡 Wow 1：让真实番剧数据"活"起来——卡牌即追番档案。**
每张动画卡背后是真实的 `rating_score`（9.2）、`rating_rank`（全站第 1）、`date`（2004 放送）、`synergy_tags`、`main_characters` + `actors`（声优）。
设想：卡详情页显示"Bangumi 全站排名 #1 · 评分 9.2 · 2004 年放送 · 你的收藏中此声优配了另外 7 个角色"。再进一步——**"我的番剧年表"**：把你拥有的动画卡按真实放送年份铺成一条时间轴，"你的收藏跨越 1998→2023，最爱 2006 年"。**没有任何虚构 IP 的抽卡游戏能做这个，因为它们的角色没有真实世界坐标。** 这是 AnimePlay 唯一的、结构性的护城河。

**💡 Wow 2：声优羁绊网（Seiyu Web）。**
数据里每个角色都挂着 `actors`（声优）。把"同一声优配音的角色"连成网：玩家拥有田中敦子配的草薙素子后，系统提示"你还差 3 个田中敦子角色集齐声优全收集"。**按声优做收集任务和图鉴**——这是 anime 死宅最上头的维度（追声优远比追番更硬核），且竞品（虚构 IP 抽卡）物理上做不到。

**💡 Wow 3：角色羁绊等级 + 故事/语录解锁。**
当前养成的好感度无上限却什么都不解锁。给它装"羁绊等级"（好感阈值升级），每级解锁：一段该角色的真实番剧介绍/名台词、一个属性里程碑奖励、满级给一张专属"羁绊卡面"或称号。把冷冰冰的数值养成变成有情感回报的"陪伴感"，这是养成系玩家自发安利的点。

**💡 Wow 4（轻量但传播力强）：可分享的"图鉴成绩卡 / 抽卡运势"。**
生成一张漂亮的 SVG/Canvas 成绩图——"我的图鉴 312/665 · UR 28/66 · 本月欧气值 ★★★★☆"，一键下载分享。死宅最爱晒收集进度和欧非。零联机依赖，纯前端可做。

### 口碑传播点分析（用户会因为什么安利？）

1. **"它认识我看过的番"**——真实数据带来的"懂行"感，是工具型用户转化的钩子。
2. **晒收集**——图鉴完成度 + 成绩卡，收集型玩家的核心炫耀欲。
3. **声优彩蛋**——"我抽的两个角色居然同一个声优"这种发现欲，是 anime 圈天然的话题。
4. **欧非梗**——抽卡运势/保底进度可视化，是手游社区永恒的传播素材。

### 值得删掉或简化的东西

- **🗑️ 简化"猜角色"或将其降级为"每日一题"。** 当前它是一个独立 8 卡级别的玩法，但深度最浅（单模式、只有最高分），却占了一个一级导航位。建议**不再当独立大模块投入**，而是改造成首页/每日任务里的"今日猜角色"小挂件（每天 1 道，连对计入成就），把省下的产品精力投到留存主线上。它的像素化资产和模糊匹配逻辑都能复用，只是不该再当"第 6 个玩法"扩张。
- **次选：合并"挑战塔"与"养成"的入口认知。** 两者强耦合（养成只为喂塔），但 UI 上是两个割裂导航项，新人不理解关系。可在养成页加"去爬塔验证战力 →"、塔页加"战力不够？去养成 →"的互导，降低割裂感（这是补强不是删除）。

## Technical Health（附带简扫）

- **架构扩展性**：良好。S2-S4 已抽出纯净 `engine/` 层（零 Vue/Pinia/DOM、RNG 可注入、lint 闸强制依赖向下），新玩法逻辑天然可测、可与未来 Node 服务端共享。存档 schema 显式集中（`infra/persistence/schema.ts`），新增字段三处同改有明确约定。**加新功能的地基是干净的。**
- **隐忧 1 — userStore 仍是偏大的兼容门面**（~300 行编排），新功能若图省事往里堆会重新长成 god store。新增的每日任务/成就/图鉴应建独立领域 store，**不要进 userStore**。
- **隐忧 2 — 存档体积随功能膨胀**：后端按用户名整体 JSON 读写（非增量）。成就/图鉴/每日任务进度都会进存档，注意字段设计紧凑（用位图/计数而非逐条对象），否则单档膨胀。`SerializedPlayerState` 已有 `watchedAnime: number[]`，图鉴完成度可复用同款"id 数组"思路。
- **性能**：S9 已优化（首屏 317KB、大列表虚拟化、gzip），无紧迫瓶颈。图鉴若渲染 665 个灰色占位格，复用现成 `VirtualGrid` 即可。
- **测试**：305+ 测试 + lint 闸 + type-check，迭代速度有保障。新领域 store 按惯例补特征测试即可。
- **安全**：S10 已加固（密码账号 + token 闸 + 原子写 + 乐观并发 + CORS 收敛 + debug 门控）。无新增审计红线。
- **小债**：`CollectionsView.vue:37` 有个面向用户暴露的"虚拟化开关"`enableVirtualization`，属调试残留性质的 UI，可顺手收掉（非阻塞）。

## Prioritized Recommendations

> 面向 Planner：本产品是**单机网页抽卡游戏**，以下建议全部"单机即成立、一个 Vue 视图 + 一个独立 store 可交付"。工作量按"一轮 product-loop 能否做完"标注。**强烈建议本轮优先做 🔴-1 与 🔴-2，它们是装动机引擎，性价比最高。**

### 🔴 Critical（缺的标配，阻止走向"真产品"）

**🔴-1. 每日任务 + 每日登录奖励（留存引擎第一块）**
- 做什么：新建 `stores/daily.ts`（领域 store）+ 主页一个"今日任务"面板组件。每日 0 点重置（复用 `rotation.ts` 的日期判定思路），3-4 个轻量任务（抽卡 1 次 / 赢 1 场对战 / 看完 1 部番 / 互动 1 次养成），做满给券+知识点；外加"每日登录"一次性发放。任务进度挂到现有玩法的成功回调上（抽卡/对战结算/收取观看）。
- 为什么：三类竞品的共同头号留存机制，AnimePlay 完全空缺。这是"明天为什么回来"的直接答案。
- 工作量：**一轮可完成**。一个 store + 一个面板 + 在现有 4 个玩法的成功点埋 4 个 `daily.markProgress()` 调用 + schema 加一个紧凑字段（当日任务进度 + 日期 + 已领标记）。

**🔴-2. 图鉴 / 收集完成度 + 里程碑奖励**
- 做什么：`CollectionsView` 增加"图鉴"视图（或新 `stores/codex.ts` 派生）：显示"动画 X/总数、角色 X/665、各稀有度 X/Y"进度条；未拥有卡显示灰色剪影占位（复用 `VirtualGrid`）；设几档完成度里程碑（如角色 100/300/500/集齐某稀有度）发奖励。
- 为什么：665 张卡的补全欲是收集型游戏最强成瘾点，目前完全没被利用。让"集卡"本身变成有目标、有奖励的进度轴（对标 Snap Collection Road / Pokédex）。
- 工作量：**一轮可完成**。完成度是从现有 `animeCollection`/`characterCollection` + `gameDataStore` 全量派生的 computed，里程碑奖励状态进 schema（一个"已领里程碑 id 数组"）。

### 🟡 Important（显著提升完整度）

**🟡-3. 成就系统**
- 做什么：`stores/achievements.ts` + 一个成就墙视图/弹窗。定义 ~20-30 条静态成就（首张 UR、爬塔 25/50 层、养成满级、猜角色连对、知识点累计、图鉴里程碑……），在各玩法成功点检测解锁，给徽章 + 一次性奖励。存档存"已解锁 id 数组"。
- 为什么：手游/卡牌标配，把散落的"高光时刻"变成可累积、可炫耀的资产，强化每个玩法的目标感。
- 工作量：**一轮可完成**（与 🔴-1/🔴-2 共享"在玩法回调里埋检测点"的模式，建议紧接其后做）。

**🟡-4. 知识点商城（经济出口）**
- 做什么：在抽卡商店旁加"知识点兑换"标签页：用知识点换券、换皮肤解锁（`skins.ts` 的 `unlock` 字段已为此预留！）、换里程碑外观。
- 为什么：当前知识点只进不出，经济失衡。给它消耗出口让所有"给知识点"的奖励重新有意义。
- 工作量：**半轮~一轮**。复用 `shop.ts` 模式，`profile.spend('knowledgePoints')` 出口已存在。

**🟡-5. 角色羁绊等级 + 解锁内容**
- 做什么：养成的好感度上加"羁绊等级"阶梯，每级解锁该角色真实番剧介绍/台词、属性里程碑、满级给称号或专属卡面。
- 为什么：把冷数值养成变成有情感回报的陪伴，养成系玩家的安利点。
- 工作量：**一轮**（数值阈值 + 解锁内容数据 + 养成页 UI 段落，需准备文案/数据，是其中较重的一条）。

### 🟢 Nice-to-have（power-user / 体验优化）

**🟢-6. 卡组分享码（编解码 + 复制粘贴）**
- 一个纯函数把卡组 id 列表编码成短字符串 + DeckManager 加"导出码/导入码"按钮。零联机依赖，卡牌品类刚需，且为 S12 多人铺路。工作量：**半轮**。

**🟢-7. 收藏高级排序/分组 + 导航红点提示**

**🟢-8. 轻量 onboarding（首登引导）**
- 首次登录的 3-4 步遮罩引导（这是抽卡→这是收藏→去打第一场对战），首抽庆祝弹窗，收藏空状态加 CTA 按钮。工作量：**半轮**。
- 注：onboarding 建议在 🔴-1/🔴-2 落地后做，这样引导才有"明确的下一步"可指（"完成今日任务领券 →"）。
