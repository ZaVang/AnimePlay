# AnimePlay Evolution Audit Report — 家园与装备进化审计

> Step A / Product Evolution Reviewer only. 本报告只读项目文档与源码，不修改源码。审计范围：`README.md`、`frontend-vue/CLAUDE.md`、`docs/plans/SPRINT.md`、`docs/plans/pitfalls.md`、`docs/FUTURE.md` S13、家园/装备/养成/挑战塔相关源码与上一轮 C2 eval 记录。竞品参考使用公开资料链接，结论落到 AnimePlay 当前 Vue + Pinia + engine 纯函数架构。

## Executive Summary

产品进化成熟度：**6.7 / 10**。

AnimePlay 的家园与装备已经从“概念页”跨到“能闭环的系统”：家园入住角色会离线产出经验/好感/知识点，养成页能补习和配装，挑战塔能掉装备，装备能通过背包和 picker 接入五维与战力，C2 eval 也确认 type-check / test / build / 后端安全基线全过。当前最大机会不再是“接通链路”，而是把链路做成二游玩家愿意每天回来的**可规划、可表达、可优化**系统。家园目前更像一块漂亮的挂机广场，缺少设施、舒适度、角色偏好、任务/派遣和回归目标；装备目前是 15 件固定平铺数值道具，缺少套装、词条、成长、分解、锁定、推荐与角色构筑差异。本轮最适合的进化方向是：先做低风险的 **家园经营目标层 + 装备目录/套装/回收/推荐层**，避免直接跳到大规模随机遗物系统。

## Phase 1: 核心完整性

**当前核心循环分析**

- 已形成基础闭环：抽卡/收藏获得角色 → 家园入住 → 离线结算经验、好感、知识点 → 角色升级随机加点 / 好感里程碑 → 挑战塔验证战力 → 掉落或兑换装备 → 配装提升五维和战力 → 挑战更高塔。
- 家园实现路径清晰：`HomesteadView.vue` 读取 `homestead.placedCharacterIds`，进页 `settleHomestead()`，入住角色在俯视广场漫步，管理弹窗从已拥有角色中选择最多 6 人入住。
- 家园经济是轻量且防刷的：`config/homestead.ts` 只放槽位、离线封顶、经验/好感/KP 产出常量；`userStore.settleHomestead()` 先按 `lastSettleAt` 结算，再推进基线，入住/移出前会先结算。
- 装备实现路径也清楚：`config/equipment.ts` 有 3 槽 × R/SR/SSR/HR/UR 的目录、兑换价、掉落层段；`stores/equipment.ts` 管 inventory/equipped、单件单戴、同槽校验、反序列化清洗和 `resolveEquipBonus`；`NurtureView.vue` 与 `SquadBattleView.vue` 共享同一个装备加成口径。
- 掉落与兑换来源已闭环：挑战塔通层后 50% 掉 1 件，稀有度随层段；知识点商店可指定购买，且走 `profile.spend('knowledgePoints')`。
- 测试基础可信：上一轮 eval 记录装备 store / 掉落 / 来源新增专项测试，迁移层覆盖 homestead/equipment 脏档，整体 50 个测试文件、563 测试全绿。

**缺失的关键环节**

- 家园缺少“经营目标”。当前只有“谁入住”和“挂机多久”两个变量，没有设施等级、舒适度、主题套装、岗位、产线、角色偏好或可升级目标。玩家能收收益，但不能规划家园。
- 家园缺少“回归提示”。导航只有主页/收藏红点，没有 homestead 可收取收益、入住已空、收益封顶、好感可领、装备掉落待处理等信号。玩家不知道什么时候该回来。
- 家园与装备的关系仍弱。家园产 KP/经验/好感，装备来自塔/商店；但家园不能制造装备、强化装备、展示已穿装备，也不能因角色/装备组合改变产出。
- 装备缺少“构筑”。当前装备只有固定 flat stat bonus，三槽各 5 件，玩家最优解几乎就是穿最高稀有度。没有套装、词条、等级、分解、锁定、推荐、角色专属效果、阵容联动或高阶 sink。
- 装备来源缺少“掉落反馈仪式”。塔日志会显示掉落，但没有独立奖励卡、背包入口跳转、首次获得提示、重复件处理建议或“下一层可掉什么”的预期管理。
- 新手路径不够顺。玩家登录后未必知道“先去家园放人、再去塔、再回养成配装”。已有 onboarding 偏全局，家园/装备没有任务链式引导。

**空状态和边界情况覆盖**

- 空状态基本存在：未登录、无角色、无装备、无同槽候选都有提示。
- 存档边界较好：家园入住会去重截断；装备会清孤儿 uid、重复装备、异槽装备，降低脏档放大战力风险。
- 经济边界较好：KP 兑换余额不足不发货，塔掉落只在 `pve.completeFloor(floor)` 真推进时触发，避免刷已通低层。
- 明显缺口是“库存膨胀边界”：重复低稀有装备会积压，没有分解/合成/出售；未来扩充目录后会变成首个体验压力点。

**本产品缺少的标配功能**

- 家园标配：舒适度/繁荣度、设施升级、装饰或主题套装、角色互动、可收取提示、派驻/轮班、产出预览、容量升级。
- 装备标配：装备锁定、分解/出售、筛选排序、推荐配装、套装效果、升级/强化、重复件处理、来源说明、掉落预览。
- 二游长线标配：每日回归仪式、红点与收益封顶提示、短期/中期/长期目标梯度、角色偏好带来的“我懂这个角色”的反馈。

**竞品用户反馈中的机会点**

- 成熟家园/基地系统常被玩家优化成“效率问题”：明日方舟基建有布局与干员组合讨论，原神尘歌壶有信任/能量/货币效率，蔚蓝档案咖啡厅有舒适度和 AP/Credit 产出。AnimePlay 可以先提供轻量规划，不必做复杂建造。
- 竞品痛点是维护负担和随机装备压力。AnimePlay 是单机网页项目，反而可以走“可解释、低痛苦”的装备深度：少做刷海量随机，先做套装/分解/推荐/定向强化，让玩家感到聪明而不是被概率折磨。
- AnimePlay 有真实 Bangumi 数据和“动画宅人格”主线，可以把装备/家园做成作品记忆与收藏表达，而不是复制通用宿舍和遗物。

## Phase 3: 功能深度

**现有功能的深度评估**

- 家园：表现层比系统层更完整。俯视广场、sprite/chibi/原立绘三级兜底、rAF 漫步让它有“活着”的感觉，但策略层只有入住名单和时间结算。当前是 M1 可用，不是 M2/M3 经营。
- 装备：架构层比内容层更完整。store 不变式、纯函数、UI picker、塔/商店来源都稳；内容层只有 15 件固定 stat stick，扩充前必须先决定“效果语法”和“重复件去向”。
- 养成：C1 精简后足够清楚，等级随机加点 + 好感里程碑 + 装备槽构成一个可理解角色页；但补习和挂机都只推数值，缺少角色性格反馈。
- 挑战塔：已成为装备验证场，但掉落池对玩家不可见，装备改变后也没有“推荐你挑战第 N 层 / 预计胜率 / 可掉落”的前后反馈。

**可能的 power-user 路径**

- 一键最强配装：基于 `calculateBattlePower` 对每个角色、每个槽计算 delta，给“推荐装备”或“自动给当前小队配装”。这是当前纯函数体系最容易支撑的 power-user 功能。
- 装备套装/系列：在 `EquipmentDef` 增加 `series` / `setId`，三槽穿同系列触发额外 flat bonus 或简单条件 bonus，不需要改 inventory 存档。
- 装备分解与合成：重复 R/SR/SSR 分解为 KP 或“记忆碎片”，碎片定向兑换 HR/UR 或升级套装，解决库存膨胀并增加长线 sink。
- 家园收益预览：展示当前入住每小时产出、封顶倒计时、下一次值得收取时间、每个角色本次将升几级/到哪个好感档。
- 家园派驻角色技能：短期不做复杂设施，可以先给角色按 rarity/tag 派到“学习桌/放映角/资料库”三类岗位，岗位决定产出偏向。

**集成、协作、自定义的可能性**

- 与收藏/图鉴集成：拥有某作品/题材的角色或动画，解锁家园主题摆件、套装蓝图、装备系列。无需新增随机系统，也能把收藏价值外显。
- 与好感集成：好感里程碑不只给 KP，可解锁该角色偏好的家园互动、装备铭刻或小型语音/台词。当前 `BOND_MILESTONES` 可以承接奖励结构。
- 与挑战塔集成：每 5 或 10 层给一个装备系列目标，让玩家知道“为什么继续爬”。掉落预览和首次通层奖励可以在 `SquadBattleView` 结果面板呈现。
- 与主页集成：主页/导航加入“家园收益已满”“装备背包有新 UR/可分解”“好感可领”的轻提醒，让循环入口更早出现。

## Phase 4: 差异化与 Wow Factor

**如果能 XXX 就太酷了**

1. **作品主题房间 / 番剧套装**：玩家拥有某部番的动画卡 + 角色卡 + 相关装备后，家园解锁一个主题角落，例如“EVA 同步测试间”“轻音部活动室”“万事屋客厅”。它同时是视觉表达、收藏成就和轻收益加成。
2. **名场面装备觉醒**：装备不只是“朗基努斯之枪 +98 ATK”，而是“来自某作品记忆的道具”。当穿戴角色的好感、所属番剧收藏或塔层达成条件满足时，装备觉醒一句短叙事和一个简单效果，如塔战首回合加 SP、家园 KP +X%、同题材角色加成。
3. **宅力工坊**：家园中增加“放映角 / 资料库 / 手作台”三设施。入住角色按题材或稀有度派驻，产出不同资源：经验、好感、KP、装备碎片、主题蓝图。它把明日方舟基建的生产链做轻，把原神/蔚蓝档案的空间表达做轻。
4. **配装顾问**：在养成页显示“当前背包里让该角色战力提升最大的 3 件装备”和“给当前小队整体提升最高的交换方案”。这很适合单机网页项目，也能立刻消化装备扩充带来的选择压力。
5. **家园回归结算演出**：离线收益弹窗不只是数字，展示本次哪些角色升级、哪些好感档推进、是否触发装备/主题发现。让回归的一秒钟变成“啊，角色真的在替我生活”。

**口碑传播点分析**

- 最有传播潜力的不是“又做了一个宿舍”，而是“动画宅的家园会根据你收集的番剧长出主题房间和名场面道具”。这和 Bangumi 数据天然绑定，竞品难直接复制。
- 第二传播点是“装备不是刷垃圾，而是作品梗 + 构筑推荐”。把装备系统从数值表变成会讲二次元梗的收藏物，符合 AnimePlay 的产品气质。
- 第三传播点是“家园、好感、塔、装备互相解释”：我把喜欢的角色放进家园，她成长，带去打塔，掉到属于某部作品的装备，再回家解锁主题角落。

**值得删掉或简化的东西**

- 不建议本阶段做自由摆家具编辑器。原神级摆放、load、碰撞、路径、保存布局会吞掉大量实现预算，而且与当前 6 人挂机闭环不成比例。先做“设施卡片 + 主题房间解锁 + 舒适度/效率”更合适。
- 不建议直接做星穹铁道式 6 槽随机主副词条。当前战斗属性只有 5 维，小队战规模较小，随机词条会制造库存管理负担。先做确定性套装、分解、升级和推荐。
- 装备扩充不应只是把 15 件变 100 件 flat stat。没有效果语法和回收机制的扩表会让玩家更困惑，也让平衡难度线性增加。

## Technical Health

**架构扩展性风险**

- 当前优点：`engine/` 纯净、RNG 注入、`stores/` 编排、schema/migration/adapter 三处持久化规则明确。家园和装备都没有把 Vue/Pinia 反向引入 engine，这是后续能安全扩展的核心资产。
- 装备效果扩展风险：如果把“效果”直接写进组件或 store 分支，很快会重演旧技能“描述≠行为”问题。建议先定义 `EquipmentEffect` 的小型白名单语法，并以纯函数把已装装备解析为 `StatBonus` / `RewardModifier` / `HomesteadModifier`，再由对应系统消费。
- 存档升级边界：仅扩充静态目录、套装定义、推荐算法不必升档；若新增装备实例等级、锁定、经验、随机词条、家园设施等级、家具库存，就必须升 `SAVE_VERSION` 并改 schema/migrations/persistence adapter。
- `config/equipment.ts` 未来会膨胀。若扩到 50+ 装备和多套效果，建议拆成 `equipment/catalog.ts`、`equipment/sets.ts`、`equipment/effects.ts` 或纯数据 JSON + typed adapter，避免单文件成为数值泥球。
- 家园视觉 rAF 当前上限 6 人可接受；若未来扩到几十角色或家具交互，需要 visibility pause、低频 tick 或只在可见区域动画。
- 文档漂移需收敛：`pitfalls.md` 顶部仍有历史 sprint 路径/版本陈述与当前 `docs/plans/SPRINT.md`、`SAVE_VERSION = 14` 不完全一致，虽然后文已补 S13-C2 沉淀。下轮若继续 product-loop，先避免依据旧段落误判。

**关键性能瓶颈**

- 装备推荐若暴力扫描“所有角色 × 所有装备 × 小队组合”可能变重，但当前背包规模小。可以先做单角色/当前小队局部推荐，并缓存 `defId → bonus`。
- 家园管理弹窗目前遍历拥有角色，注释里也提到规模变大可改 VirtualGrid。若未来玩家拥有上千角色，管理入住应复用 `VirtualGrid` 或按 rarity/tag 搜索筛选。
- 掉落/兑换扩充后，背包组件的聚合逻辑会被频繁触发；当前 computed 足够，但随机词条/等级加入后要小心不要每帧或每个 hover 重算全背包。

**测试与质量保障状态**

- 当前质量基础较好：装备 store、掉落、来源、迁移均有测试；上一轮 eval 也复核了 engine 纯净、RNG 注入、spend/earn 入口、防刷和 equipBonus 同源。
- 后续新增效果必须补“行为=描述”测试：每种 `EquipmentEffect` 至少有纯函数测试 + 一个消费端集成测试。
- 下轮顺手修小债：`InventoryPanel.vue` 选中稀有度按钮曾被 eval 记录存在 `bg-accent\15` 的 Tailwind 透明度写法瑕疵，应改为 `bg-accent/15`；`SquadBattleView.vue` 有 pre-existing ESLint 残留，若碰该文件可顺手收。

## Prioritized Recommendations

### 🔴 Critical：缺失的标配功能，阻止产品走向市场

1. **家园目标层 MVP：收益预览 + 可收取红点 + 下一步目标**
   - 目标：让玩家进家园前就知道“有收益可收 / 收益快封顶 / 哪个角色要升级或好感可领”。
   - 范围建议：不先升档；用现有 `placedCharacterIds`、`lastSettleAt`、nurture 数据纯派生。加导航红点、家园顶部收益预测、封顶倒计时、收取后升级/好感摘要。

2. **装备重复件出口：分解/回收低稀有装备**
   - 目标：扩充装备前先解决库存膨胀，避免玩家拿到第 10 把木刀只能看着。
   - 范围建议：先做 `def.rarity → KP/碎片` 的确定性回收，走 `profile.earn`，只删 inventory uid；若加锁定再升档，否则先不做锁。

3. **装备效果语法先行：套装/系列加成，而不是继续 flat stat 扩表**
   - 目标：装备系统从“高稀有度必穿”变成“按角色/阵容/玩法选择”。
   - 范围建议：给目录加 `series`，穿 2/3 件同系列触发额外 `StatBonus`；不新增实例字段、不升档。先做 5-8 个系列，每系列 3 槽，覆盖攻击、坦度、速度、KP/掉落倾向等。

### 🟡 Important：显著提升产品完整度的功能

1. **扩充装备目录到 45 件左右**
   - 目标：每槽每稀有度不止 1 件，让掉落和商店有选择。
   - 范围建议：3 槽 × 5 稀有度 × 3 系列。每件保留动漫名梗，但归入系列，例如“同步率”“轻音部”“侦探社”“魔法少女”“赛博义体”。先保证数值预算和套装效果表可读。

2. **配装顾问 / 一键推荐**
   - 目标：扩装备后仍不让玩家迷路。
   - 范围建议：单角色推荐最高战力 delta；当前小队推荐“最小交换集合”。复用 `generateBattleStats`、`calculateBattlePower`、`resolveEquipBonus`，不引入新存档。

3. **家园三设施轻经营**
   - 目标：把“入住 6 人”改成“派到不同设施”。
   - 范围建议：学习桌产经验、放映角产好感、资料库产 KP/装备碎片。若需要记录每个设施分配，升 v15；若想先零升档，可按入住顺序切 2/2/2 做概念验证，但正式版建议升档。

4. **挑战塔奖励面板**
   - 目标：把装备掉落从日志提升到奖励仪式。
   - 范围建议：胜利结果区展示装备卡、来源、是否新获得、按钮跳养成/背包；塔入口展示当前层可掉稀有度与下一档层段。

### 🟢 Nice-to-have：power-user 功能、体验优化

1. 背包排序与筛选升级：按战力 delta、是否装备中、重复数量、可分解排序。
2. 装备锁定与批量分解：一旦装备目录扩张，这是必要 QoL；锁定需要升档。
3. 家园角色互动：点击入住角色可摸头/送礼/显示今日一次好感小奖励，借鉴蔚蓝档案但保持轻量。
4. 家园主题角落展示：先做解锁展示墙，不做自由摆放；主题由玩家收藏/套装达成派生。
5. 移动端基础可用性：当前 App 明示桌面优先，但家园/养成是重复访问页面，至少保证按钮和弹窗在窄屏不遮挡。
