## Phase 1：核心完整性

**当前核心循环（装备获取侧）已闭环但有一处「反馈黑洞」**：
- 获取来源两条：① 塔通层 50% 随机掉落（`rollFloorDrop`，命中→随机槽→层段稀有度→目录内 `rng.pick`）；② KP 定向兑换（`purchaseEquipment`，走 `profile.spend`，任意目录件可买）。
- 出口三条已在 S14 补齐：分解回收 KP（`dismantleValueForRarity`）、强化燃料（`enhancedBonus` 吃同 defId 重复件）、套装凑齐（`setBonusFor`）。
- **缺口 = 掉落侧零定向零保底**：兑换虽可定向但要 KP（UR 24000，高门槛）；免费的掉落全凭运气。想要「特定套装的最后一件」或「某槽 UR」时，除了砸 KP 就只能刷脸——`rollTowerDrop` 掷 chance→掷 slot→定 rarity 三步全随机，**连开 50 层不出目标槽是完全可能的**。这正是 P3-3「掉落纯随机无定向」的体验代价。

**S15-T4 要补的核心环节 = 给「运气」加一条确定性下界**，让「持续投入必有定向回报」成立。这不是新增玩法，是给已闭环的获取循环补上「反馈保证」——收集向游戏的核心完整性底线。

**空状态 / 边界情况**（T4 必须覆盖）：
- pity 计数从 0 起（新档 / v19→v20 旧档迁移补 0），首次命中即重置。
- 顶层（floor≥999，`completeFloor` 返 false 不掉落）/ 重复挑战低层（不推进不掉落）**绝不推进 pity 计数**——pity 只在「真掉落判定发生」的分支累加，否则毕业玩家扫荡刷保底又是一个墙钟/刷取漏洞。
- pity 触发后强制命中的槽/稀有度仍要落在目录覆盖内（`getEquipmentDefsBySlotRarity` 兜底 `rng.pick`，起始目录全覆盖，防空候选）。

## Phase 2：竞争差距

对标两条主流定向范式（均已用 WebSearch 核实）：

| 产品 | 定向机制 | 对 AnimePlay 的借鉴 |
|---|---|---|
| **明日方舟 / Endfield** | 武器/干员 gacha「N 抽保底」双阶梯（如 6★ 保底 40/80，武器 4/8 抽保底 featured） | **保底范式**：连续未出→强制命中。纯确定性，最贴单机向、最省改动。**本轮首选。** |
| **公主连结 PCR** | Hard 模式每日刷「记忆碎片」→ 商店按角色定向兑换；地下城币/竞技场币换碎片 | **碎片范式**：日循环发碎片→定向换指定件。体验重但要新货币 + 新兑换 UI + 新发放埋点。 |
| **星露谷 / 蔚蓝档案** | 非装备定向，但都靠「投入必有稳定回报」维持长线粘性 | 印证「反馈保证」是收集/经营游戏的 table stakes，不是锦上添花。 |

**本产品缺的标配 = 「保底」这条 table stakes**：所有主流 gacha 都有保底，AnimePlay 的装备掉落却是裸随机。项目**自己的 gacha 已有成熟保底**（`engine/gacha/draw.ts` `PityState`：70 抽保底 HR、十连保底 SSR），装备掉落只是**没把这套现成范式接过来**——和 S14「个人技 effectId 已有却没接进小队战斗」同型的「现成能力未接通」缺口，属高杠杆低成本。

**竞品痛点本产品有机会规避**：方舟/PCR 的碎片刷取伴随体力墙 + 每日刷刷刷疲劳（PCR Hard 每关每日 3 次）。AnimePlay 单机向无体力，**若做碎片必须用周期封顶**（仿 `SWEEP_WEEKLY_CAP`）防「无限刷保底通胀」，否则重蹈 AFK 死区。这也是**保底方案更优**的又一理由：保底天然绑在「真实通层/扫荡产生的掉落判定」上，不制造独立刷取循环。

## Phase 3：功能深度

**保底方案（a）的深度锚点（首版做透即可，别过度设计）**：
- **计数粒度**：建议「按稀有度或按槽」二选一做**单一维度**，别做「稀有度×槽」二维矩阵（计数字段爆炸 + 玩家心智负担）。最贴挫败感的是「稀有度 pity」——连续 N 次未出当前层段应出的稀有度（如已在 51+ 层却连续掉不到 UR）后强制出。
- **阈值**：N 取「体感能感知但不破坏惊喜」的中值（如 8~10 次未出保底），远小于 gacha 70，因为装备掉落频率低（50% × 每层一次）。config 顶部集中一个 `DROP_PITY_THRESHOLD` 常量，改这里即调平。
- **纯函数签名**：`rollTowerDropWithPity(floor, rng, rarityForFloor, pity, config) → { drop, pity }`（仿 `performDraws` 传入/返回 pity，调用方写回）——**不就地改 pity，engine 纯净不碰持久化**。
- **防退化 3 条**：① pity 计数只在「掉落判定真发生（推进新层）」时累加，顶层/重复层/扫荡不碰（防墙钟刷保底）；② 触发命中的候选池空时仍 `rng.pick` 兜底不抛错（目录全覆盖，防御）；③ pity 计数持久化字段**复用 v20**（挂进 `TowerProgress` 扁平字段，仿 `sweepUsedThisWeek`；三处同改 + 往返测试），**绝不升 v21**（Scout C-1 版本漂移守则）。

**碎片方案（b）若被 Planner 选中（不建议但备案）的深度守则**：碎片走独立计数（非 `profile` 货币，避免污染 KP 语义）或复用 KP；发放绑扫荡/委托/成就已有埋点（`markCommission('tower')` / achievements）；兑换复用 `purchaseEquipment` 范式；**必须周期封顶**防通胀。改动面 ≈ 保底的 2~3 倍。

**power-user 路径**：保底让「刷特定套装最后一件」从「刷脸」变成「保底兜底」，配合 S14 已有的套装（`setBonusFor`）/强化（`enhancedBonus`）形成「定向获取→凑套/强化」的完整 build 路径——这是把 S14 装备深度真正盘活的收尾接线。

## Phase 4：差异化与 Wow Factor

**「如果能 XXX 就太酷了」（≥3，全标 backlog，不进本轮）**：
1. 💡 **保底进度可视化「运气条」**：塔探索面板显示「距下次保底还有 N 层」的进度条 + 命中瞬间「保底触发！」飘字——把不可见的 pity 计数显形（对齐 S15-T3/T2-E 的「显形命门」教训，避免又造一个死数值）。本轮若时间充裕可顺手做一格进度提示；否则 backlog。
2. 💡 **套装定向选择券**：高层通关低概率掉「选择券」→ 玩家钦点某套某槽的一件（PCR 定向兑换的轻量版），把「凑套最后一件」的挫败感彻底消除。backlog（需新道具 + 新 UI）。
3. 💡 **番剧主题掉落池**：入住某作品角色时，该作品「梗装备」（如 EVA 队伍→AT力场掉率提升）——把 968 番真实数据的独特资产接进掉落，是竞品无法复制的差异化方向。backlog（需装备↔作品映射数据）。

**口碑传播点**：保底本身不是传播点（是 table stakes），但「运气条 + 保底触发飘字」的**确定性反馈爽感**能显著降低挫败流失——收集游戏的留存命脉。真正的传播点仍是家具布局（S15-T2）+ 番剧主题（backlog #3）。

**值得删掉 / 简化的东西（≥1）**：
- **删掉「重新刷新敌人」按钮的残留心智**（若仍在）——原始审计 P2-17 已修「预览≠实战」统一种子，但 T4 做 pity 时若引入任何「刷新掉落」入口会重演同型困惑，**明确不做「重roll 掉落」**，保底是唯一定向手段。
- **简化 pity 维度**：拒绝「稀有度×槽」二维矩阵，单维度即够——过度设计的保底矩阵是新手流失点。

## Technical Health（附带扫描，非全面审计）

- **架构扩展性**：健康。engine 纯净铁律未破（`drops.ts` 零 `Math.random`/零 store import），pity 纯函数天然契合「注入 RNG + 传入/返回状态」范式，无扩展性风险。gacha `PityState` 已证明该范式可复用。
- **存档协议风险（本轮唯一需盯死点）**：pity 若持久化，**必须三处同改（schema type + migrations + persistence 装配器）+ 往返测试 + v19→v20 旧档补 0**，且**复用 v20 绝不升 v21**（一 Sprint 一 bump 铁律，Scout C-1）。历史「文档版本漂移」坑家族的高发区，Evaluator 须核 `SAVE_VERSION===20` 断言未被误改成 21。
- **性能瓶颈**：无。pity 是 O(1) 计数，掉落判定每层一次，无热路径。
- **测试与质量**：现状扎实（前两轮 test×3 全绿，`equipmentSource.test.ts` 已锁掉落 RNG 注入范式）。T4 特征测试可直接仿 `createSequenceRng` 序列 RNG 断言 pity 边界（连 N 次未出→第 N+1 次必命中目标类），成本低、覆盖强。**回归守卫**：顶层/重复层/扫荡不推进 pity 的确定性测试必须新增（防墙钟刷保底）。
- **安全 / 隐私**：S15 不碰后端，`debug=True` 零命中基线维持；单机向掉落不涉多人/排行，无新攻击面（墙钟刷取风险由「pity 只在真掉落分支累加」的回归守卫覆盖）。

## Prioritized Recommendations

### 🔴 Critical（本轮必须落地的指派切片 = S15-T4）
- **[S15-T4] 装备定向保底（pity）纯函数 + RNG 注入**：`rollTowerDropWithPity` 传入/返回 pity（仿 gacha `performDraws`），连续 N 次未出目标类后强制命中，engine 纯净不碰持久化。config 顶部集中 `DROP_PITY_THRESHOLD`。特征测试断言 pity 边界（连 N 次未出→第 N+1 次必命中）。
- **[S15-T4] pity 计数持久化复用 v20（若持久化）**：挂 `TowerProgress` 扁平字段（仿 `sweepUsedThisWeek`），三处同改 + 往返测试 + v19→v20 旧档补 0，**SAVE_VERSION 保持 20 绝不升 21**。
- **[S15-T4] 防墙钟刷保底回归守卫**：pity 只在 `completeFloor` 推进新层的真掉落分支累加；顶层（≥999）/ 重复低层 / 扫荡（`sweepFloor`）**绝不推进 pity**——新增确定性回归测试断言之。

### 🟡 Important（本轮做透的深度守则）
- **[S15-T4] 单维度计数，拒绝二维矩阵**：按「稀有度」或「槽」单选一维做保底，别做「稀有度×槽」矩阵（字段爆炸 + 心智负担）。建议做「稀有度 pity」（最贴挫败感）。
- **[S15-T4] 保底命中候选池空的兜底**：强制命中后仍 `getEquipmentDefsBySlotRarity` + `rng.pick`，空池不抛错（目录全覆盖，防御）。
- **[收尾] 确保 S15-T1..T4 全 `[x]`、S14 33 项无回归**：本轮是 Sprint 收尾轮，Evaluator 须核全清单 checkbox 与实现一致 + test×3 全绿 + `SAVE_VERSION===20`。

### 🟢 Nice-to-have（低成本体验优化，本轮时间充裕可顺手）
