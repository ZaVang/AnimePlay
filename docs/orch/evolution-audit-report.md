## Executive Summary

**产品进化成熟度评分：7.0 / 10**（Round 1 的 6.0 → 7.0）

第 1 轮把"动机引擎"装上了，效果立竿见影：现在新人登录会自动领登录奖励、首页有今日任务面板、收藏多了图鉴/成就两个 tab、665 张卡第一次有了"X/665 完成度 + 灰位剪影 + 里程碑"。**最重要的是它建成了一套统一事件面**——`daily.markProgress(type)` 与 `achievements.check(event, payload)` 在 6 个玩法成功点并排埋设（抽卡/对战胜/收看/养成/猜对/通层）。这是本轮最宝贵的遗产：**任何"基于玩法事件"的新功能都能零成本挂上去，不必再改那批编排函数。**

但留存引擎目前是"装好了地基，只盖了一层"：

- **每日任务只有 4 条单日任务**，无周任务、无连续登录累计、无"全部完成"额外奖励——做完今天的 4 条就再无可做，缺"做下去"的长尾。
- **图鉴只有"按稀有度"一个维度**，9 个里程碑全是 ownedCount/rarityComplete。665 张卡背后真实的 `anime_names`（按番剧分组）、`date`（放送年表）、`actors`（声优）三个差异化维度一个没用上。
- **成就 18 条扁平铺开**，无分类、无进度型（"赢 10 场"解锁瞬间靠会话计数，墙上看不到"7/10"）、无稀有度档次。

而本轮被产品方明确点名的两个主题，现在到了非解不可的时刻：

**① 经济闭环已从"隐患"升级为"硬伤"。** 上轮我说"知识点只进不出"，这轮校正一个事实：**出口其实存在**——GachaShop 能用知识点买卡/券（UR 1500 KP、HR 800 KP、SR 券 60 KP…）。真正的病根更精确：**这个出口被锁死在"当天 UP 轮换的那 2 张卡"上**。玩家在图鉴里盯着某张缺的 UR 灰位，却买不到它——只能等它某天轮换进商店（665 卡、每天轮 2 张，期望等待以年计）。第 1 轮的 daily/里程碑/成就又在疯狂产出知识点，于是"攒了几万知识点却没有想买的东西"成了肉眼可见的失衡。**图鉴那一格格"未拥有"的灰位，正是知识点最该流向的目的地，现在它们是死的。**

**② onboarding 时机已经成熟。** 上轮我说"等 daily/图鉴落地了引导才有下一步可指"——现在落地了。而且后端早有 `isNewUser` 标志（`api.ts:11`）却只用于初始化存档、**完全没驱动任何首次体验**。新人首抽没有庆祝、收藏空状态只有一句死文案、没有任何"完成今日任务领券 →"的指路。

**最大进化机会在 Phase 4 差异化 + Phase 1 经济闭环的交叉点**：把**图鉴**从"只读的完成度面板"升级成**经济与差异化的枢纽**——既是知识点的消耗目的地（targeted unlock），又是真实元数据（评分/年表/声优）的展示舞台。

一句话定位：**第 1 轮装上了动机引擎，第 2 轮要给它接上"油箱出口"（让知识点能买到你真正想要的那张卡）和"独家燃料"（让真实番剧数据从后台 JSON 变成玩家看得见、玩得到的收集维度）。**

## Phase 1: 核心完整性

### 当前核心循环分析（Round 1 后）

留存主线现在是闭的，但很短：

```
登录 → 自动领登录奖励（券×2）
     → 首页今日任务面板：抽1次/赢1场/收看1次/养成1次 → 领券+知识点
     → 收藏→图鉴 tab：看 X/665 完成度，达里程碑领奖
     → 收藏→成就 tab：看已解锁 N/18
```

**闭环质量评估**：每日任务确实回答了"明天为什么回来"，但**回来之后 10 分钟就做完了**——4 条任务各 target=1，没有"今天还能做什么"的第二层。图鉴/成就是"被动累积"的，玩家不会每天专程去看。**留存引擎现在像一个只有 4 格的签到表，缺"阶梯"和"长尾"。**

### 缺失的关键环节（按本轮影响排序）

1. **🔴 经济出口与收集目标脱节（本轮头号硬伤）。** 知识点的唯一有意义出口（买卡）只覆盖当天 UP 的 2 张。玩家在图鉴看到自己缺哪些卡，却没有任何"花知识点把这张缺的卡补进图鉴"的路径。**收集的"目标"（图鉴灰位）和经济的"出口"（商店）是两套互不连通的系统。** 竞品（Marvel Snap Token Shop）的核心正是把这两者焊死：货币 → 定向解锁你缺的那张卡。

2. **🟡 每日任务无纵深。** 无周任务（累计型，给玩家跨天追的目标）、无连续登录递增日历（竞品公认的 loss-aversion 钩子——"别断签"比"今天登录"更黏）、无"今日全清"打包奖励。当前 4 条做完即止。

3. **🟡 图鉴维度单一，浪费真实数据。** 只有"稀有度"一个切面。`selected_character` 数据里每张卡都带 `anime_names`/`anime_ids`/`anime_count`（实测 100% 覆盖），却没有"按番剧看：命运石之门 角色 3/5"这种最自然的收集分组；`selected_anime` 每张都带 `date`（1963→2025）/`rating_score`/`rating_rank`（实测 100% 覆盖），也没有年表或评分维度。

4. **🟡 成就缺进度可视化与分类。** "赢 10 场对战"在墙上只显示锁/未锁，看不到"7/10"；18 条平铺无分组（抽卡/对战/收集…）、无稀有度（普通/稀有/传说成就），缺"差一点点就解锁"的牵引力。**注意**：当前成就累计计数 `stats` 是会话级（不进存档），跨会话靠"已解锁 id 幂等"——意味着进度型成就若要显示"7/10"需要把计数持久化，是有真实成本的改动（见 Technical Health）。

5. **🟡 onboarding 仍为零。** `isNewUser` 标志现成但未用。首抽无庆祝、收藏/图鉴空状态无 CTA、新人面对 8 导航项+今日任务面板仍无"先做这个"的指引。

### 空状态与边界情况

- 图鉴空状态**反而是亮点**：灰位剪影 + "未拥有"角标，天然就是"还差这些"的可视化——这正是 targeted unlock 该挂的钩子（点灰位 → "花 X 知识点解锁"）。
- 收藏 anime/character 空状态仍是纯文字死状态（"找不到匹配的卡"），无 CTA。
- CardDetailModal **完全没展示真实元数据**：动画卡只显示 TP cost / 效果 / 标签 / 简介，`rating_score`/`rating_rank`/`date` 全在数据里却不显示（数据已送达前端，仅 `main_characters` 被后端剥离）。这是差异化最低垂的果实。

## Phase 2: 竞争差距

### 竞品对比（聚焦本轮三主题）

**A. 经济 sink — Marvel Snap Token Shop（直接可借鉴的范式）**

| 机制 | Marvel Snap | AnimePlay 现状 |
|---|---|---|
| 收集进度产出专用货币 | Collector's Tokens 沿 Collection Level Road 发放 | 知识点（daily/里程碑/成就大量产出）✅ |
| 货币定向解锁**你缺的**特定卡 | Token Shop 只卖你未拥有的卡，可定点购买 | ❌ 只能买当天 UP 轮换的 2 张 |
| 终局循环 = 攒货币补齐图鉴 | Series 3 集齐后进入 token→补卡的长期循环 | ❌ 图鉴与商店不连通 |
| 重复卡回收成货币 | dupe → 资源/货币 | ✅ 分解→知识点（已有） |

> **机会点（本轮最高 ROI）**：AnimePlay 已经有了 Snap 模型的两端（收集进度产货币 + 重复卡回收货币），**唯独缺中间那根管子**——把知识点直接花在图鉴里你缺的那张卡上。这不是抄袭，是把已有的两个孤岛连起来。

**B. 货币 sink 与 dupe-craft（gacha 通用范式）**

竞品（NTE/DanMachi/Trickcal）的共识：满命/重复卡转成"卡晶"，到另一个商店**定向兑换想要的卡**；攒币等 dream 角色 UP。核心都是**给随机抽卡配一个确定性出口**。AnimePlay 的随机性（双池+保底）已足够，缺的正是这个确定性出口。研究还反复警告反例（Dragalia Lost）：**货币种类堆太多 + 到处弹窗 = 体验崩坏**。对 AnimePlay 的启示——别新增货币，就用现成的知识点开出口，保持单一货币的清爽。

**C. daily / weekly / streak 纵深（留存机制深化）**

研究结论：成熟产品**daily（appointment 习惯）+ weekly（跨天目标）+ 连续登录递增日历（loss-aversion）三层叠加**。Clash Royale/Free Fire 的递增签到日历用"别断"的损失厌恶驱动回访，比固定奖励更黏。AnimePlay 现在只有最薄的一层（4 条单日 + 一次性登录奖励），且登录奖励不递增——**"连续 7 天"这种最强钩子完全没有**（讽刺的是 viewing.ts 里早埋了个"连续 7 天观看"奖券，但藏得没人知道）。

**D. 收集深度与可分享（追番工具 + Wrapped 文化）**

AniList Wrapped / MAL Wrap-Up / MiyoList 每年刷屏，证明**"把你的收集/口味生成一张漂亮可分享的卡"是 anime 受众的核心传播行为**。AnimePlay 握着同源真实数据（评分/年份/声优）却一点没往这个方向用。

### 本产品仍缺的"桌上赌注"汇总（本轮维度）

1. **图鉴定向解锁**（收集型 + 卡牌品类的现代标配，Snap Token Shop / dupe-craft）——本轮最该补。
2. **周任务 + 连续登录日历**（留存三层的后两层）。
3. **收集的非稀有度维度**（按作品分组 = 追番工具刚需；按年份/评分 = AnimePlay 独有）。
4. **真实评分/放送信息展示**（CardDetailModal 该有而没有）。
5. **成就进度可视化**（手游/卡牌通用，"差一点"的牵引）。

## Phase 3: 功能深度

### Round 1 留存引擎深度评估

| 模块 | 当前深度 | 判断 |
|---|---|---|
| 每日任务 | **浅** | 4 条单日 target=1，无周/无累计/无连签/无全清奖励。容器建好了，内容只有一层 |
| 图鉴 | **中等偏浅** | 完成度+灰位+里程碑做得扎实，但只有稀有度一个维度，真实元数据三矿（作品/年份/声优）未开 |
| 成就 | **中等偏浅** | 18 条覆盖 6 玩法，但无进度可视化、无分类、无稀有度，计数会话级（跨会话不显示进度） |
| 经济出口 | **浅且错位** | 出口存在但锁死在 UP 轮换，与收集目标脱节 |

### 可深化路径（复用已有事件面，边际成本低）

- **每日任务 → 任务体系**：在 `dailyTasks.ts` 同款配置里加 `WEEKLY_TASKS`（累计 target，如"本周赢 10 场""本周收看 20 次"），store 加一个按"周键"（年-周序号）判定重置的 `weeklyProgress`——**埋点完全复用现有 markProgress 的同一批调用，只是 daily store 多遍历一张周任务表**。再加连续登录计数（`loginStreak` + `lastLoginDate` 已有），按递增日历发奖。
- **图鉴 → 多维收集**：completion 已是纯派生 computed，加"按作品分组"只是换一种 `groupBy(anime_names)` 的派生 + 新里程碑类型（如"集齐某热门番全角色"）。**零新存档**（除了新里程碑的已领 id 复用现成数组）。
- **成就 → 进度型 + 分类**：配置加 `category` 与 `target` 字段，墙上渲染 `current/target` 进度条。代价是把 `stats` 持久化（schema 加一个紧凑计数对象），换来"差一点就解锁"的牵引。

### Power-user / 自定义（与上轮一致，仍空缺，非本轮重点）

快捷键、批量操作、收藏高级排序/分组、卡组分享码、导入导出——均仍为零。其中**收藏按"放送年份/评分/拥有数量"排序/分组**会随本轮"真实元数据可视化"自然解锁（数据一旦在 UI 暴露，排序就是顺手的事），可作为差异化项的附带产出。

## Phase 4: 差异化与 Wow Factor

> 本轮把上轮列在 backlog 的 💡-9/💡-10/💡-11 提为**可落地评估**——经实测，真实数据全部已送达前端（仅 `main_characters` 被后端剥离），可落地性比上轮判断的更高。

### "如果能 XXX 就太酷了"

**💡 Wow 1（本轮强烈推荐落地）：图鉴即番剧档案 + 真实评分/年表。**
实测：`selected_anime` 250 张**全部**带 `rating_score`/`rating_rank`/`rating_total`/`date`（年份 1963→2025）。
- **CardDetailModal 加一段真实档案**：「Bangumi 评分 9.2 · 全站排名 #1 · 2011 年放送 · 共 1.1 万人评价」。纯前端、零后端、半天工作量，立刻把"抽卡奖品"变成"有真实世界坐标的番剧卡"。
- **图鉴加"年表"视图**：把拥有的动画卡按 `date` 铺成时间轴——"你的收藏跨越 1998→2024，最爱 2011 年（5 张）"。**没有任何虚构 IP 的抽卡游戏能做这个**，这是结构性护城河。

**💡 Wow 2：按作品 / 按声优的收集维度（图鉴第二、第三切面）。**
- **按作品**（零后端）：`selected_character` 665 张**全部**带 `anime_names`/`anime_count`。图鉴加"按番剧分组"——"命运石之门：角色 3/5""集齐某番全角色"里程碑。这是追番受众最自然的收集心智。
- **按声优**（需轻量后端）：实测 selected 数据含 **459 位声优**（全量 1085 位，神谷浩史配 51 角、花澤香菜 33 角…）。"集齐花澤香菜配音的全部角色"是 anime 硬核圈最上头的维度，竞品物理上做不到。**⚠️ 可落地性提醒**：声优数据藏在 `anime.main_characters[].actors`，而后端 `server.py:44` 服务时**剥离了 main_characters**（占 94% 体积）。所以声优维度**不是纯前端**——需后端额外吐一个精简的 `角色id→声优` 映射（或新开 `/api/seiyu` 端点）。比按作品维度重，建议作为差异化的"第二步"。

**💡 Wow 3：可分享的"图鉴 Wrapped 成绩卡"（口碑传播引擎）。**
AniList Wrapped / MAL Wrap-Up 每年刷屏，证明 anime 受众极爱晒收集。前端 Canvas/SVG 生成一张"我的图鉴 312/665 · UR 28/66 · 收藏跨越 1998→2024 · 本月欧气 ★★★★☆"，一键下载。零联机、零后端、纯派生现有数据。这是把图鉴完成度变成传播素材的临门一脚。

### 口碑传播点分析（本轮新增/强化）

1. **"它认识我看过的番，还告诉我它全站第几"**——真实评分/排名带来的"懂行"感（Wow 1）。
2. **"我抽的这俩居然同一个声优"**——声优维度的发现欲（Wow 2），anime 圈天然话题。
3. **晒 Wrapped 成绩卡**——收集型玩家核心炫耀欲（Wow 3）。
4. **"终于把缺的那张 UR 用知识点补上了"**——targeted unlock 带来的满足感分享（经济闭环副产品）。

### 值得删掉或简化的东西（本轮）

- **🗑️ 简化"猜角色"为图鉴/每日挂件（上轮提议本轮重申）。** 它仍占一个一级导航位，深度最浅（单模式+最高分），且与本轮"图鉴枢纽化"方向天然契合——可降级为图鉴里的"今日猜角色"小挂件（每天 1 题，连对计入成就/任务）。本轮不强求，但若做图鉴改造顺手可并。
- **🗑️ 警惕"货币堆叠"陷阱（来自竞品反例 Dragalia Lost）。** 做经济出口时**坚决复用现有知识点单一货币**，不要为 targeted unlock 新发明"碎片/卡晶"二级货币。研究明确：货币种类膨胀 + 满屏弹窗是体验杀手。AnimePlay 现在货币清爽（3 种），这是优点，别破坏。

## Technical Health（附带简扫）

- **统一事件面是本轮最大资产**：`drawCards`/`battleFlow.endGame`/收看/养成/猜对/通层 6 处已并排调 `markProgress` + `achievements.check`。**周任务、进度型成就、任何新的"基于玩法事件"功能都从这里挂，不必改编排函数**——这是第 1 轮留下的最好的地基。
- **图鉴完成度是纯派生 computed**（遍历 gameDataStore 全量卡 + collection 计数），新增"按作品/按年份"分组只是换 groupBy，**零新存档字段**。新里程碑复用现成"已领 id 数组"。
- **存档协议 v6 已立**，新增字段三处同改（schema/migrations/装配器）约定清晰。本轮若加周任务进度/连签计数/成就计数，**注意字段紧凑**（用计数对象而非逐条对象，参照现有 `progress: Record<string,number>`）。
- **⚠️ 进度型成就有真实成本**：当前 `AchievementStats` 是会话级 reactive（不进存档），解锁靠"已解锁 id 幂等"。要在墙上显示"7/10"必须把计数持久化进档——这是进度型成就唯一的非平凡改动点，需评估值不值（也可只对"累计型"成就持久化计数，"瞬时型"如首抽 UR 不需要）。
- **声优维度需后端配合**：`server.py:44` 剥离 main_characters，actors 数据不到前端。按作品/年份/评分维度是纯前端，按声优维度需新端点——这是 Wow 2 拆成两步的根因。
- **经济出口落地点明确**：`profile.spend('knowledgePoints', cost)` 出口现成，`collection.addCard(id, type)` 入库现成。targeted unlock 就是"spend 成功 → addCard → 存档"，无新基础设施。
- 测试 336 + lint 闸 + type-check 健在；性能 S9 已优化，图鉴年表/分组复用 VirtualGrid 无瓶颈。安全 S10 已加固，无新红线。
- **小债（顺手可清）**：CardDetailModal 的 `[key: string]: any` 卡类型兜底导致真实字段无类型提示——做 Wow 1 时可顺手给 AnimeCard 补 `rating_score?`/`date?` 等可选字段类型（非阻塞）。

## Prioritized Recommendations

> 面向 Planner：本产品是**单机网页抽卡游戏**，以下全部"单机即成立、一个 Vue 视图/面板 + 一个 store（或纯派生）可交付"。**所有"基于玩法事件"的项复用第 1 轮已建的 markProgress/check 统一事件面，不再改编排函数。** 工作量按"一轮 product-loop 能否做完"标注。

### 🔴 Critical（本轮硬伤，阻止经济与收集闭环）

**🔴-1. 图鉴定向解锁（Codex Targeted Unlock）—— 经济出口 × 收集目标的焊接点**
- 做什么：在 CodexPanel 的灰位（未拥有卡）上加"花知识点解锁"入口——点未拥有的卡 → 弹"花 X 知识点把它补进图鉴"（X 按稀有度定价，复用 gameConfig 现成的 dismantleValue 量级反推，如 UR 1500 KP）。`spend('knowledgePoints')` → `collection.addCard` → 存档。可加每日解锁次数上限防一夜补满（复用 shop 的 todayKey 限购模式）。
- 为什么：**本轮最高 ROI。** 一举解决两个被产品方点名的主题——知识点的有意义出口（不再锁死 UP 轮换）+ 图鉴灰位从"死的"变成"目标"。直接对标 Marvel Snap Token Shop，是收集型游戏的现代标配。daily/里程碑/成就疯狂产出的知识点终于有了配得上的去处。
- 工作量：**半轮~一轮**。无新存档字段（addCard 走现成 collection），无新货币（复用知识点）。改动集中在 CodexPanel + 一个 userStore 编排函数（spend+addCard+存档）+ 可选的每日限购计数。
- ⚠️ 守住：**不发明二级货币**，就用知识点（竞品反例 Dragalia Lost 的教训）。

### 🟡 Important（显著提升完整度）

**🟡-2. 周任务 + 连续登录递增日历（留存三层的后两层）**
- 做什么：① `dailyTasks.ts` 加 `WEEKLY_TASKS`（累计型，如"本周赢 10 场""本周收看 20 次"），daily store 加按"周键"重置的 `weeklyProgress`——**埋点 100% 复用现有 markProgress 调用**。② 登录奖励改递增日历（`loginStreak` 计数 + 7 天循环递增表，断签归零），用 loss-aversion 驱动连续回访。
- 为什么：当前留存引擎只有最薄一层；竞品研究证明 daily+weekly+streak 三层叠加才是成熟形态，连签的"别断"钩子比固定奖励更黏。
- 工作量：**一轮**。store 加两块状态（周进度 + 连签计数）进 schema（v7），面板加周任务区 + 连签日历条。逻辑与现有 daily 同构。

**🟡-3. 真实番剧元数据可视化（CardDetailModal 评分/年份 + 图鉴年表）**
- 做什么：① CardDetailModal 加"番剧档案"段：真实 `rating_score`/`rating_rank`/`rating_total`/`date`（数据已在前端）。② 图鉴加"年表"视图：拥有的动画按 date 铺时间轴 + "你的收藏跨越 X→Y"。
- 为什么：AnimePlay 唯一的结构性护城河，竞品物理上做不到；实测数据 100% 覆盖、纯前端、半天起步。把"抽卡奖品"变成"有真实坐标的番剧档案"。
- 工作量：**半轮**（CardDetailModal 段落）~**一轮**（含年表视图）。纯派生，零后端，顺手给卡类型补可选字段类型。

**🟡-4. 成就进度可视化 + 分类**
- 做什么：成就配置加 `category`（抽卡/对战/收集…）与 `target`，墙上按类分组 + 显示 `current/target` 进度条。
- 为什么：把"差一点就解锁"变成牵引力；18 条平铺缺纵深。
- 工作量：**一轮**（含 stats 持久化的取舍——见 Technical Health，可只对累计型成就持久化计数，瞬时型不动，控制成本）。

### 🟢 Nice-to-have（power-user / 体验优化）

**🟢-5. 轻量 onboarding（首登引导）—— 时机已成熟**
- 做什么：用现成 `isNewUser` 标志驱动：首抽庆祝弹窗（sparkles/confetti，2025 best practice）、3-4 步遮罩引导（这是今日任务→这是图鉴→去补第一张缺卡）、收藏/图鉴空状态加 CTA。
- 为什么：上轮说"等 daily/图鉴落地引导才有下一步"——现在落地了，且 isNewUser 现成未用。引导终于有明确终点可指（"完成今日任务领券 →""去图鉴补张缺卡 →"）。
- 工作量：**半轮**。无新存档（isNewUser 后端已给；"已看过引导"可用一个布尔进档或 localStorage）。

**🟢-6. 收藏按真实维度排序/分组**
- 做什么：收藏加按"放送年份/评分/拥有数量"排序、角色按作品分组。
- 为什么：随 🟡-3 数据暴露自然解锁，power-user 刚需。
- 工作量：**半轮**（数据一旦在 UI 可用，排序就是顺手的）。

### 💡 Feature Idea（差异化创新，放 backlog / 第 3 轮候选）

- **💡-7. 声优收集维度**：按 `actors` 做"集齐某声优全角色"图鉴与里程碑（459 声优）。anime 硬核圈成瘾点、竞品物理做不到。**⚠️ 需后端吐精简 角色→声优 映射（main_characters 当前被剥离）**，故列为 backlog 而非本轮——但这是第 3 轮差异化主题的最强候选。
- **💡-8. 图鉴 Wrapped 成绩卡**：Canvas/SVG 生成可分享的收集成绩图（完成度+年份跨度+欧气）。AniList Wrapped 验证的传播引擎，纯前端。第 3 轮"传播"主题候选。
- **💡-9. 卡组分享码 / 一键导入 Bangumi 看过列表**：上轮 backlog 延续，单机异步分享 + 工具用户转化，远期高粘性。

### 给 Planner 的一句话结论

**本轮（Round 2）最高 ROI 的组合是 🔴-1（图鉴定向解锁）+ 🟡-3（真实评分/年表可视化），二者都以"图鉴"为枢纽、都复用现成 `spend`/`addCard`/纯派生基础设施、几乎不进新存档，一个 Sprint 内可一并落地。** 它一箭双雕地解决产品方点名的两大主题——把图鉴同时变成**知识点的消费目的地**（经济闭环：灰位不再是死的）和**真实数据的展示舞台**（差异化护城河：竞品物理上做不到）。如果还有余量，再叠 🟡-2（周任务+连签）补留存纵深。第 1 轮装了动机引擎，第 2 轮就该让"图鉴"从只读面板进化成全产品的价值枢纽。
