# 家园 hub 最终审计报告

> **方法论**：从第一性原理出发 + 公主连结（PCR）对标，对家园 hub（`/homestead`，5 个 tab：家园/角色/编队/探索/战斗）做对抗性审计。
> 8 个维度并行审计（战斗方法 / UI-UX / 角色养成 / 技能配置差异化 / 装备属性多样化 / 功能整体完善度 / 代码漏洞 / 经济与成长闭环），
> 每条发现由 **4 个独立对抗性 agent 投票**（代码求证 / PCR 对标公平性 / 严重性质疑 / 用户体验影响）：≥3 票记「确认」、2 票「争议」、≤1 票「否决」。
> 规模：225 个 agent、约 1024 万 token、1340 次工具调用。产出 54 条发现 → 确认 50、争议 3、否决 1。日期：2026-07-01。
> 范围严格限定家园 hub，不涉及宅理论战/抽卡/收藏/小游戏/设置。

## 一、总体判断

**结论：家园 hub 目前是一套「五环拼装的半成品」，视觉与信息架构已经搭好、底层数值管线已经打通，但作为一个收集向养成循环，它在「差异化—决策—闭环」这三个决定可玩性的关节上同时断裂。** 它能跑、不崩、数字算得对，但玩家在其中几乎做不出任何有意义的选择，收集来的角色在战斗里彼此无法区分,养成动作是掷骰子,家园经营是看数字,爬塔卡关即断更。

三条最致命的系统性根因：

1. **角色差异化被架空（战斗层同质化）**。200+ 角色在小队战斗里坍缩成 6 个原型模板，同原型角色技能数值逐字节相同，只换中文名；项目其实已经拥有一套 66×2 条唯一技能资产（/battle 域在用），却在小队战斗里"只借名不借效果"。抽卡收集的核心动机——"抽到心动角色→在战斗里体验她的独特性"——在 PVE 里完全落空。

2. **养成与配装没有玩家决策**。升级是随机加点直接注入实战五维且不可洗点；装备是任意角色戴任意装、纯线性五维、拿到即终态；角色无 role 定位，可以练出"全堆攻击的坦克"。玩家对"我怎么变强"没有任何操作空间，成长退化为纯数值膨胀。

3. **循环闭环缺失，卡关即断更**。挑战塔是一次性单调递增进度，通过的层不可重刷产出，塔外无任何可重复 PvE；家园设施纯展示不可升级、挂机产出恒定不随进度成长；KP 唯一硬通货的 sink 全是"买断即枯竭"的一次性目录。玩家一旦卡在打不过的那层，家园 hub 内再无主动产出与短期目标——"一周后还有没有理由回来"的答案是"卡住=没事做"。

这三条不是零散 bug，而是同一个病根的三种表现：**系统的骨架（UI/数据/管线）做完了，但填充骨架的"选择空间"没做**。修复方向不是推倒重来，而是在既有管线上"接线"——很多缺口（暴击框架、个人技 effectId、编队编辑 action、设施标签）代码底子都在，只差把已有能力接通。

## 三、系统性根因

把 40+ 条发现归纳为 5 个根因：

### 根因 A：角色在战斗层完全无差异化
6 原型模板（`squadSkillKits.ts:200 archetypeEffects`）决定一切，per-character 只换名字；个人技 effectId（`urCharacterSkillsGenerated.ts`，/battle 域已实现 134 handler）在小队战斗里被 `getSquadSkillKitForCharacter` 只取 `.name`（`squadSkillKits.ts:393-409`）；HR 连名字都不换全走原型；正则 `inferArchetype` 猜定位频繁误判。**收集游戏的核心资产（角色独特性）在最核心的循环（PVE 战斗）里被抹平。**

### 根因 B：养成/配装没有玩家决策
升级随机加点（`rules.ts:61-71 distributeRandomStatPoints`）+ 不可洗点 + 无 role 定位（`types/nurture.ts` 无 role 字段）+ 装备任意戴任意（`equipment.ts:82` 只校验槽位）+ 纯线性五维无词条/套装/强化。**"变强"这件事上玩家只能灌资源，做不出任何 build 选择。**

### 根因 C：无可重复循环 + 卡关即断更
挑战塔单调递增、通过层零收益（`pve.ts:46-49` + `rewards.ts:57-64`）；塔外无可重复 PvE；家园挂机恒定不成长（`config/homestead.ts`）。**没有任何机制把落后队伍拉回来，也没有"每天回来"的理由。**

### 根因 D：家园无机制闭环（设施是装饰）
三设施纯展示不可升级（`HomesteadView.vue:182-186`，全仓无 facility store/config）；comfort 全链路只展示不生效（死数值）；挂机↔战斗两条平行线互不喂养。**家园缺"基地随时间/投资变强"这条本应承接 KP sink 的自循环。**

### 根因 E：经济终局塌陷
KP 是唯一硬通货但 sink 全是买断目录（装备 45 件封顶、图鉴、补习）；无无底 sink；重复装备无回收/分解出口；经验曲线（满级 980 万）与产出（每层几百）严重错配、满级后产出全沉没。**成型账号 KP 只增不减、经验打进黑洞、奖励全面失效。**

## 四、确认发现（按 severity 分组）

> 注：本次投票产出的最高共识 severity 为 P1；无 P0。以下 P1 为"必须修才能称为完整玩法"的项。

### P1 — 必须修（系统性根因项）

**P1-1｜角色技能实为 6 原型模板，同原型数值逐字节相同，战斗零个体差异**
- 维度：战斗方法 / 角色技能配置差异化（两维度重复确认，合并）
- 证据：`squadSkillKits.ts:200-382 archetypeEffects` 纯 switch(archetype) 返回写死 effects；`getSquadSkillKitForCharacter:384-413` 仅把 name 拼进标题（:400/:404/:409），effects 全来自原型。两个 striker 的 skill1 都是 atkRatio1.25+spRatio0.2、大招都是 atkRatio2.2+execute0.16。
- PCR 对标：PCR 每角色 4 条完全唯一技能（唯一倍率/UB/机制），是收集与配队核心动机。
- 影响：抽到新 UR 只要原型撞车，战斗表现与已有角色一模一样，收集/养成长期驱动力被抽空。
- 建议：让个人技能驱动至少一条差异化技能位（skill1 用角色专属 effect）；或每原型加 3-4 数值档按 rarity/stats 分档；头部 20 个招牌 UR 手写唯一 kit，其余回落原型。

**P1-2｜urCharacterSkills 唯一技能（含 effectId）在小队战斗里只取 .name，效果整块丢弃**
- 维度：角色技能配置差异化
- 证据：`urCharacterSkillsGenerated.ts` 每 UR 有 2 条完整个人技（description/cost/cooldown/effectId），effectId 在 /battle 有 134 个真实 handler；但 `squadSkillKits.ts:393-394` 只用 `.name`，effects 一律来自 archetypeEffects。
- PCR 对标：招牌技能名与机制一体。项目已拥有 66×2 唯一技能设计资产却"只借名不借灵魂"。
- 影响：制造"描述≠行为"的观感欺骗（技能叫"时间理论"/"GEASS命令"，实际跑通用模板），正是 CLAUDE.md Known Debt 明令根除的"宣称未执行的效果"换域重现。
- 建议：让小队战斗复用个人技 effectId/数值（把 /battle handler 映射到 squad effect）；否则名字也回退原型名以免误导。**（这是把最能差异化的现成素材接通，属高杠杆项）**

**P1-3｜编队/探索/战斗三 tab 与 SquadBattleView 内嵌爬塔页信息三重重复，前两者只读**
- 维度：UI/UX（多条重复确认，合并）
- 证据：`HomesteadHubView.vue:339-388` squad tab 只读站位（无 @click）、:390-431 explore 只读预览、:433-439 直接内嵌 `<SquadBattleView/>`；而 `SquadBattleView.vue:619-753` towerMode 已完整重绘可编辑版本（:675-751 槽位 @click=openCharacterSelect 换人、改队名、开始挑战）。
- PCR 对标：PCR 编成页即操作页，一屏闭环，绝不给两屏只读预览+第三屏可编辑同样内容。
- 影响：五 tab 里三 tab 是同一件事的不同保真度切片，是 hub 最大结构性冗余。
- 建议：二选一——(A) squad tab 成为唯一编队入口（站位可点开换人，复用 CharacterSelectModal），explore 保留预览+"开始挑战"直接触发，battle 只承载演出；(B) 删掉 squad+explore 两只读 tab，把 towerMode 编成屏作为 explore 内容。

**P1-4｜编队面板完全只读——无法在 hub 里换人/建队，站位是 affordance 欺骗**
- 维度：UI/UX / 功能整体完善度（重复确认，合并）
- 证据：`HomesteadHubView.vue:365-386` formation-slot 无 @click、无编辑；`pve.ts:19 updateSquadMember`/`:27 updateSquadName` 存在且经 `userStore.ts:659-660` 暴露，但 hub 内从未调用（仅 SquadBattleView/CharacterSelectModal 用到）。面板标题却写"开战前可见"暗示这是备战主界面。
- PCR 对标：PCR 编成天然是"编辑"而非"查看"。
- 影响：用户看到像编成界面的东西却点不动，卡在 tab 找不到出口。
- 建议：给 formation-slot 加点击→复用 CharacterSelectModal + `userStore.updateSquadMember`，squad-select 加改名，空位显示可点"+添加"。**（编辑 action 已存在，仅需接线，低成本高收益）**

**P1-5｜升级随机加点直接注入实战五维，零 build 决策且不可洗点**
- 维度：角色养成
- 证据：`rules.ts:61-71 distributeRandomStatPoints` 逐点 rng.int 随机落五维；`rules.ts:77-88` 每级 roll 10 点；`nurture.ts:109-114` 累加进 statPoints；`SquadBattleView.vue:215 buildCharacterStats` 用 generateBattleStats 喂进真实战斗；`combat.ts:144-156` 纯加法。Lv.100 累计 990 点全随机，与 base 同量级。全仓无 respec（grep 零命中）。
- PCR 对标：PCR 成长完全确定，同角色任意存档强度一致，乐趣在资源分配而非掷骰。
- 影响：升级这个养成核心动作对玩家是纯噪声，无法规划、不同存档强度随机波动、练废只能弃。
- 建议：改确定成长（按 base 五维比例确定分配，保持总量不变去掉 rng，一行改 store）；或保留加点池改玩家手动分配+提供洗点。

**P1-6｜挑战塔一次性单调递增，通过层不可重刷，塔外无可重复 PvE，卡关即断更**
- 维度：经济与成长闭环
- 证据：`pve.ts:46-49 completeFloor` 仅 floor===currentFloor 才推进给奖；`rewards.ts:57-64` progressed=false → 经验/KP 全 0；已通层重打恒零收益。卡关后 hub 内只剩 12h 封顶挂机（`config/homestead.ts:37`）。
- PCR 对标：PCR 有多条并行可重复日循环（地下城重刷/EXP 副本/公会战/竞技场），卡主线不影响每日产出。
- 影响：卡关玩家彻底失去主动产出与短期目标，也无机制把落后队伍拉回来。
- 建议：引入至少一条可重复日循环——扫荡已通层给缩水 KP+经验+低概率装备（加每日次数封顶防通胀）；或塔外单开经验/装备副本每日 N 次。

**P1-7｜装备无强化/精炼/升级/等级——拿到即终态，缺"核心成长闸"**（3/4，1 票认为应降级）
- 维度：装备属性多样化
- 证据：`stores/equipment.ts` 仅 addItem/equip/unequip/resolveEquipBonus，无强化入口；`EquipmentItemSave` 仅 `{uid,defId}`，实例不携带等级/强化/词条，数值恒等于 def 静态值。
- PCR 对标：PCR rank 装备是养成核心闸门，强化是持续 sink 与战力增量来源。
- 影响：装备无法承担"核心成长闸"，玩家拿到同槽 UR 即永久毕业，无可持续消耗。
- 建议：给 EquipmentItemSave 加 level/enhance（schema+migrations+装配器三处同改），用重复装备/材料做强化燃料，把毕业曲线从"拿到即满"拉长为"拿到→强化到满"。
- **分歧提示**：1 票认为已有 R→UR 五档稀有度即"换更高稀有度"的进度线、养成另有两轴，是否再叠加强化属深度取舍非硬伤，应降至 P3。**本报告采信多数票 P1，但建议：若资源紧张，此项可作为 P2 深度批处理，优先级低于 P1-1/2/3/4。**

### P2 — 应修（明显削弱深度与手感）

**战斗机制类**

**P2-1｜前中后排只是目标排序标签，对承伤/减伤/站位博弈零机制**
- 战斗方法 | 证据：position 仅在 `targeting.ts:31/45/73-79` 用于 front/backEnemy 排序；`effects.ts:159 dealDamage`、`formulas.ts:82 calculateTimedDamage` 完全不读 position。无后排减伤、无 AOE 递减、无默认按排仇恨。
- PCR 对标：站位是 PCR 编队策略一半（前排顶伤、后排站桩）。影响：编队 UI 摆 5 个前中后槽却怎么排都不影响结果，UI 承诺了机制、代码没实现。
- 建议：给 position 真实机制（后排近战减伤/AOE 衰减/前排默认仇恨）；若不做就去掉前中后排视觉避免误导。

**P2-2｜暴击系统默认失效：critRate=0，仅 striker 被动有 10% 暴击**
- 战斗方法 | 证据：`formulas.ts:5 critRate=0`；`SquadBattleView.vue:258-272` 建 setup 不传 modifiers → 全单位 critRate=0；唯一提升源 striker passive `critRateUp0.1`（`squadSkillKits.ts:371`）。canCrit/critDamage 大量出现却基本死代码。
- 建议：给全体基础 critRate（如 0.05）并让装备/养成/buff 能加暴击做成真实成长轴；或彻底删除 crit 字段避免死系统误导。

**P2-3｜同类 buff/debuff 取最大值而非叠加，团队增益无协同**
- 战斗方法 | 证据：`effects.ts:47-52 maxRuntimeStatusValue` 同 kind 取 Math.max；两个 support spUp0.08/0.15 最终只吃 0.15。
- 建议：可叠加类（atkUp/defDown/spUp/critRateUp）改按来源累加设上限，控制类（stun/silence）保持不叠加。

**P2-4｜90s 超时一刀切判负，无倒计时/进度提示**
- 战斗方法 | 证据：`timedBattle.ts:25 MAX_TIME_MS=90000`，`:97` 超时 winner='timeout' → defeat 不发奖；`SquadBattlefield.vue:24` 只显 elapsedMs 无倒计时。高防/治疗局可能占优却被判输。
- PCR 对标：PCR 也有 90s 时限但有醒目倒计时，TIME UP 按剩余总血量比例判胜。
- 建议：UI 加倒计时/进度条；超时改按双方剩余 HP% 裁决而非固定判负。

**P2-5｜手动大招只能改开大时机、改不了目标、且每次整场重算**
- 战斗方法 | 证据：`timedBattle.ts:276` autoUltimates 默认 true；`handleManualUltimate:469-477` 塞 order 后 regenerateBattleSimulation 整场重算再回放；大招目标仍是 skill 写死 selector。
- 建议：让手动大招能选目标；默认设关或首战引导手动；手动开大改增量推进而非整场重算避免回放跳变。

**P2-6｜1000 能量大招按原型只有 6 种，且只有 striker 大招会暴击**
- 角色技能配置差异化 | 证据：所有 ultimate energyCost=1000（`squadSkillKits.ts:410`），target+effects 全由原型定；全 6 原型唯一施 critRateUp 的是 striker passive。66 个 UR 大招坍缩成 6 个。
- 建议：让非 striker 也有基础 critRate（或删 canCrit 死代码）；大招长期做 per-character 差异。

**角色技能/养成类**

**P2-7｜inferArchetype 靠正则关键词匹配拼接文本，误判频发且首命中即返回**
- 角色技能配置差异化 | 证据：`squadSkillKits.ts:110-128` textOf 拼 name+desc+anime+tags+技能名跑 6 条正则 first-match-wins（顺序 support→guardian→arcane→controller→tactical→striker）。误判：阿尔托莉雅命中 arcane 的 `圣剑|Fate` 被判魔法师；含"音乐/BanG Dream"角色一律先命中 support；"爆裂"角色被 arcane 抢走 striker 高倍率；synergy_tags 的"战斗"标签能把治疗角色拽成打手。
- 建议：废弃运行时正则，在角色数据显式声明 archetype 字段（生成脚本一次性人工校对 66 UR）；过渡期至少按"专属技能名>description>name>tags"加权。

**P2-8｜HR 角色无 urCharacterSkills 绑定，技能名与效果 100% 走原型模板**

## 五、争议发现（未达 3 票共识）

以下为 2/4 票的 contested 发现，单列并注明分歧核心，供决策参考。

**争议 1｜整场战斗一次性预演算+定速回放，玩家全程只是观众**（2/4，标 P1）
- 维度：战斗方法 | 证据属实：`timedBattle.ts:288 simulateTimedBattle` 一次算完，`SquadBattleView.vue:442-459` 180ms 逐条回放；普攻/skill 全自动，玩家无法选目标/打断/换技能。
- **分歧核心**：两位反对者认为对标不公平且事实夸大——手动大招时机（handleManualUltimate + auto/手动开关）恰是 PCR 的核心操作杠杆 UB timing，且每次下单会真正重演算改变结果，并非"零操作纯观众"；PCR 半自动同样不给"选目标/打断/换技能"，不构成对标缺口；这是明确标注的"半自动战斗"合理取舍。
- **报告立场**：不列为必修。战斗操作深度确实偏薄，但"手动大招时机+战前配队配装"已达 PCR 平价的半自动杠杆；建议归入 P2 战斗打磨（配合 P2-5 让手动大招能选目标+增量推进），而非 P1 推倒战斗模型。

**争议 2｜tab 导航缺 tablist/aria-selected 语义，home 深链被 replace 抹空 query**（2/4，标 P2）
- 维度：UI/UX | 证据属实：`HomesteadHubView.vue:253-265` 裸 button 无 role=tab/tablist/aria-selected；switchTab home 用 query:{} 会吞 tab 参数。
- **分歧核心**：反对者认为对单机向视觉优先游戏无实际可玩性影响——button 原生可聚焦、Enter/Space 可切换，只缺方向键与 SR 播报；home 深链被抹后仍落同一默认面板，是伪问题；属 a11y 洁癖，最多 P3。
- **报告立场**：降为 P3。a11y 语义补全是好实践但非本项目当前瓶颈，可在其它 UI 改动时顺手补 role/aria。

**争议 3｜装备加成相对基础面板占比过低，装备几乎不构成战力增量**（2/4，标 P2）
- 维度：装备属性多样化 | **判定：证据前提错误，不成立。**
- **分歧核心**：两位反对者指出该发现的分母用错了——`STAT_DISPLAY_REF`（atk 800/hp 1500）是 `config/nurture.ts:22-24` 明确标注"仅显示用、不进存档、不影响战斗"的进度条软上限，从不进战斗引擎。真实战斗面板是 `combat.ts:150-155` 的 base(character.battle_stats,约 50~250)+statPoints+equipBonus。以真实 base 计，UR 武器 atk+108 是 40%~100%+ 的增量，与塔敌 base 同量级，装备贡献并不边缘，甚至偏高。
- **报告立场**：**驳回**。整条推导建立在"幽灵分母"上，结论与事实相反，不应列入任何优先级。若担心装备权重，应以真实 battle_stats 口径重新标定，而非按 STAT_DISPLAY_REF。

## 六、改进路线图

> 原则：本项目是**单机向二次元收集网页游戏**，不追求 PCR 的付费深度与竞技强度，但"收集有意义、养成有决策、循环有产出"是收集向玩法的底线。以下区分"必须修"与"锦上添花"，并标注 ⭐ **低成本高收益**（改动小、杠杆大、多为已有能力接线）。

### 第一批 · P1 急救（把"半成品"补成"完整玩法"）

1. ⭐ **接通编队编辑**（P1-3/4）：给 formation-slot 加 @click 复用 CharacterSelectModal + 已存在的 `updateSquadMember/updateSquadName`；explore tab 保留预览+"开始挑战"直接触发，battle tab 只承载演出。**编辑 action 已存在，纯接线，一天内可落地。**
2. ⭐ **统一敌人预览种子**（P2-17，虽标 P2 但属真 bug 且极低成本，随急救批处理）：让 hub 预览与 SquadBattleView 共用 `createSeededRng(floor 派生)`，或预览读持久化 towerEnemyData。
3. **升级加点改确定成长**（P1-5）：把 distributeRandomStatPoints 换成按 base 五维比例的确定分配（保总量去 rng），一行改 store 不动存档结构；同步引入 role 字段（P2-9 复用 archetype）。⭐ 确定分配本身是低成本。
4. **给个人技能驱动至少一条差异化技能位**（P1-1/2）：让 skill1 或 ultimate 复用 urCharacterSkills 的 effectId/数值（把 /battle handler 映射到 squad effect）；头部 20 招牌 UR 优先。**这是接通已有资产、直接兑现角色差异化的最高杠杆项。**
5. **引入一条可重复日循环**（P1-6）：扫荡/重复挑战已通层给缩水 KP+经验+低概率装备，加每日次数封顶。解决"卡关即断更"。

### 第二批 · P2 体验（补手感与信息一致性）

- **战斗手感**：加 90s 倒计时+超时按剩余 HP% 判胜（P2-4）；手动大招能选目标+增量推进不整场重算（P2-5）；给全体基础 critRate 让暴击活起来（P2-2）。
- **战斗深度**：position 给真实机制（后排减伤/前排仇恨）或去掉前中后排视觉（P2-1）；可叠加 buff 改按来源累加设上限（P2-3）。
- **角色定位**：废弃正则 inferArchetype 改显式 archetype 字段（P2-7，人工校对 66 UR）；HR 补个人技能名（P2-8）。
- **UI 去重**：NurtureView 拆成无壳可内嵌组件，消除双标题/双空态（P2-18）。
- ⭐ **补挂机 delta 预览**：EquipPickerModal 加 homeEffect before→after（P2-13 的低成本子项）。

### 第三批 · P2 深度（补养成/经济/家园闭环）

- **家园机制闭环**（P2-25/26/24/13/27 一揽子）：给三设施加 level 存档域，用 KP 升级抬升挂机产出乘区，comfort 接一档真实软加成；把装备的家园 homeEffect 逐步剥离到设施，装备回归纯战斗。**这一组联动做完，家园从"单页面板"变成"经营系统"，同时开出一个无底 KP sink。**
- **经济闭环**（P2-19/20/21）：压平经验曲线或加满级溢出出口；给重复装备分解为 KP / 合成材料（同时开出装备强化 sink）；加无底 KP sink（装备强化或角色突破）。
- **养成长线**（P2-10/11/12）：补一条星级/突破长线（重复角色卡→碎片突破）；好感等级化给永久小加成+剧情解锁；塔层加战力/等级门槛把养成钉进探索。
- **装备深度**（P1-7/P2-14/16）：加装备强化（level/enhance 字段）；加确定性套装/原型条件加成（优先套装，随机副词条谨慎，与单机向定位一致）。

### 第四批 · P3 打磨（内容与一致性）

- ⭐ 删/改 hero 循环胶囊（P3-1）；⭐ 补习批量/一键升级+成本递增（P3-2）；家园驻留低频定时结算+封顶进度条（P3-8）；统一敌我战力口径（P3-6）；家园收益封顶改分层递减（P3-7）；墙钟回拨钳位（P2-28 的廉价卫生改动）。
- 中期内容：轻量家具系统（P3-4）、入住羁绊（P3-5）、家园日常委托（P3-10）、装备定向掉落保底（P3-3）。
- 可暂不处理（玩家不可感知的 latent 洁癖）：inferArchetype 稀有度兜底（P3-9）、结算复核拥有数（P3-11）——两条经模拟证实当前无可达触发路径，留待开放弃卡/脏档校验时再补。

**一句话收尾**：家园 hub 的骨架和管线都在，问题是"选择空间"没填。P1 急救里有三项（编队接线、确定加点、个人技接通）都是"已有能力接线"级别的低成本高收益改动，做完就能把 hub 从"能跑的半成品"拉到"有收集意义的完整玩法"；P2 深度批的家园设施闭环是把家园真正立起来的关键。对标 PCR 是为了照见缺口，但落地时应始终锚定"单机向收集"的定位——补差异化与循环是必须,追付费深度与随机刷取则大可不必。
