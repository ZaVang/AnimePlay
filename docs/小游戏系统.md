## 高低牌 Higher/Lower（`stores/minigames/higherLower.ts`）

给两张同类卡，左卡数值已揭示、右卡隐藏，玩家猜右卡「更高/更低」。对 → streak+1、右卡滚成新左卡再发一张；错 → 结算。

**维度按卡类型分桶（铁律，不可混用）**——实测覆盖率决定（见 Scout 实测）：

| 维度 | 卡类型 | 字段 | 说明 |
|---|---|---|---|
| 角色人气 | character | `popularity_score`（13–4050） | 数值大 = 更受欢迎 |
| 番剧口碑 | anime | `rating_total`（评分人数） | 数值大 = 评价更多 |
| 番剧年代 | anime | `date` 取年份（1993–2025） | 数值大 = 放送更晚 |

> 番剧无 `popularity_score`、角色无 `rating_rank/date`，裸 `rating_score` 仅 20 个 distinct（抛硬币）——故按卡类型分桶。选卡保证两值不等，无平局歧义。纯逻辑（选卡/判定/计分）是注入 RNG 的纯函数，配特征测试。

## 番剧问答 Quiz（`stores/minigames/quiz.ts`）

4 选 1，题目全部从真实数据**派生**（注入 RNG，确定性可测）。4 类题型：

- **角色出处**：「X 出自哪部作品」（`character.anime_names` + 干扰项）
- **番剧年份**：「X 哪年放送」（`anime.date` + 邻近年份干扰）
- **最高评分**：「下列哪部评分最高」（4 部不同 `rating_score` 取最高）
- **最高人气**：「下列哪个角色人气最高」（4 个不同 `popularity_score` 取最高）

答对 → streak+1 出下一题；答错 → 结算。

## 每日挑战 Daily Challenge（`higherLower.ts` 内 dc* 系列）

**固定种子全员同题**：当日种子 `mulberry32(YYYYMMDD)` 确定性生成 5 题（复用 Quiz 题库）——同一天所有人同题、隔天换题、可回放确定、剧透安全、**无需后端同步**。每人每天一次。

- **连续天数 streak**（`streakDays`/`bestStreakDays`）：昨日完成过则 +1，断签（含首次）归 1，历史最长保留——Duolingo 式留存抓手（连续登录 7+ 天留存约 2.4×）。

## 番剧品味画像 Taste Profile（`utils/tasteProfile.ts` + `components/TasteProfileGame.vue`）

「选番 → 报告」两态。用户在番剧网格里勾选「看过」的番（关键字搜索 + 只看已选 + 一键清空），点「生成画像」得一份分析报告。**纯分析无随机**——`buildTasteReport(已看子集, 全量库)` 是可单测纯函数（`utils/tasteProfile.test.ts`）。

报告维度（全部基于现有 Bangumi 元数据，无新数据）：

- **人格标签**：由各信号确定性推导的一句话标签（如「小众考古学家」「XX 浓度爆表」「高分鉴赏家」「时代眼泪收藏家」「杂食型阅片家」），`count<3` 时给「画像萌芽中」。
- **统计卡**：已看数 + 覆盖率 / 平均分（对比大盘 `ratingDelta`）/ 小众指数（已看番在全库 `rating_total` 分布的平均百分位取补，0–100，越高越冷门）。
- **题材偏好**：`synergy_tags` 频次条形图，剔除格式/地区噪声（日本/TV/…）与来源标签。
- **年代分布**：`date` 取年份分桶（2000 前 / 00 / 10 / 20 年代）。
- **原作来源**：漫画改/小说改/原创/游戏改 构成。
- **稀有度构成** + **代表作高亮**（最高分/最小众/最早/最新）。

> 与游戏内「观看队列已看（`viewing.watchedAnime`）」是两个概念：这里是用户手动勾选的 IRL 观看记录。无战绩、无奖励、不占每日封顶（纯收藏式分析功能）。勾选集持久化（见存档 v12），勾选即存（`userStore.toggleTasteWatched` → `saveToServer`，未登录则仅会话内有效）。

## 经济与防刷

奖励**只走 `profile.earn('knowledgePoints')`**（唯一货币入口）：

- **高低牌 / 番剧问答**：连胜里程碑发奖 `streakReward(streak) = floor(streak/5)×15`，且**跨这两个游戏共享每日封顶 `HL_DAILY_KP_CAP = 120` 知识点/天**（`awardDate`+`awardedToday` 跨天归零记账）——streak 可无限长，封顶防一局连对刷爆。
- **每日挑战**：每答对 1 题 `DC_KP_PER_CORRECT = 12` 知识点（满分 60），**每日仅首通发放**（`lastDate` 闸门），不占上面的共享封顶（是 quest 式 once/day 奖励，不可刷）。

结算编排在门面 `userStore.settleHigherLower / settleQuiz / settleDailyChallenge`：调领域 store 结算 → `profile.earn` → 推进留存埋点 → `saveToServer`。

## 留存联动（见 [留存系统.md](留存系统.md)）

玩任意小游戏结算时埋点：`daily.markProgress('minigame')`（推进「小试身手」日任务 + 「小游戏达人」周任务）+ `achievements.check('minigame', {streak})`（小游戏成就：初体验 / 单局连胜 10 / 累计 20 局）。导航红点跟随「有奖可领」派生。
