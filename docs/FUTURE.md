# AnimePlay 演进 Roadmap

这是项目唯一的前进任务源，只记录未完成方向。已完成工作见 [HISTORY.md](HISTORY.md)，具体开工前再把选中的方向拆成当期计划，不长期保留完成后的 Sprint 合同。

## 目标与边界

长期目标是可上线的多人动画收集游戏，支持排行榜与 PvP。演进过程中保持以下边界：

1. `frontend-vue/src/engine/` 保持纯净，不依赖 Vue、Pinia、DOM、网络或存储。
2. 依赖只向下，随机与时间可注入，规则能在无 UI 环境测试。
3. 每次迭代独立可合并，未完成的后续工作不能破坏当前可玩版本。
4. 玩法描述、实现和测试必须一致，不上线“只有文案、没有行为”的效果。

## 下一阶段候选

### S11 — 视图层演进

当前方向是评估是否把视图层迁移到 React，同时复用已有 TypeScript engine。该方向尚未激活，开工前必须先验证迁移收益，不默认把“换框架”当作目标。

- [ ] 用小型垂直切片验证 engine、types、config、data、infra 的真实复用边界。
- [ ] 对比继续治理 Vue 与迁移 React 的成本、风险和可维护性。
- [ ] 若迁移成立，再确定状态层、路由、构建和逐页验收策略。
- [ ] 保持现有功能与存档兼容，避免一次性全量重写。

退出条件：先形成决策完整的迁移方案；只有收益明确后才进入实现。

### S12 — 权威后端与多人闭环

- [ ] 把可共享的 engine 提升为前后端共用包。
- [ ] 建立服务端权威的战斗与抽卡结算，客户端只做展示与预测。
- [ ] 把用户与存档迁移到适合多人场景的数据层。
- [ ] 增加排行榜、匹配与 PvP，并补齐反作弊、限流和运维边界。

退出条件：多人对战与排行榜可部署、可观测，并保留现有单机数据迁移路径。

## Backlog

### 可独立决策

- [ ] 小游戏数据为空或加载失败时提供明确的重试与返回入口，避免玩家停在不可恢复的空状态。
- [ ] 家园在未登录、无角色等空状态下提供恢复 CTA，直接引导到登录或角色获取流程。
- [ ] 为小游戏返回确认和揭晓计时器补精确的 UI 竞态回归测试，覆盖快速点击、退出与卸载边界。
- [ ] 复盘 `beforeResolve` 临时强度是否应计入最终档位；当前实现会计入，只有平衡性证据出现时才改。
- [ ] 家具布局深化：评估自定义摆位的交互价值与存档成本。
- [ ] 更多角色羁绊与碎片兑换：先明确奖励轴，避免叠加新的无意义数值。

### 依赖后端

- [ ] 品味契合度对照：玩家间的品味重合与发现，需要后端和存档协议支持。
- [ ] 声优收集维度：后端先提供稳定的 `角色 id -> 声优` 映射，再设计前端玩法。
- [ ] 家园离线收益使用服务端权威时间，替代仅靠客户端墙钟的最终方案。

## 更新规则

- 开始一项工作时，把范围、非目标、验收命令和回滚边界写进当期 issue 或临时计划。
- 完成后只把稳定结论补进机制文档或 `HISTORY.md`，删除临时合同和审计快照。
- 如果方向仍在决策阶段，保留问题与门槛，不提前写成承诺。
