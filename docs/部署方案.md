# 部署方案（S10）

> 本文档配合 S10 后端加固产出。用户决策＝**只加固不实施**：这里把两条上线路径的要点列清，
> 不绑定具体平台、不真正部署。落地时按其一执行即可。
>
> S10 已加固的安全面（见 [FUTURE.md](FUTURE.md) S10）：
> - 存档接口鉴权：密码账号 + 无状态会话 token（`backend/auth.py`），读写存档须带 `Authorization: Bearer <token>` 且 token 解析出的用户名与目标存档一致。
> - 凭据独立存储在 `data/auth/credentials.json`（盐哈希），不进存档文件。
> - `debug` 默认关闭（env `FLASK_DEBUG=1` 才开）。
> - 存档原子写（temp + `os.replace`）+ `saveVersion` 乐观并发（版本冲突 409）。
> - CORS 收敛（env `ALLOWED_ORIGINS`）、vite dev host/allowedHosts 收敛（env 可放开）。
> - `Werkzeug` 已钉版本（防 3.x 与 Flask 2.3.2 不兼容）。

## 必须设置的环境变量（两条路径通用）

| 变量 | 作用 | 生产要求 |
|---|---|---|
| `SECRET_KEY` | 签发/校验会话 token 的密钥 | **必须**设为高熵随机值（如 `python -c "import secrets;print(secrets.token_urlsafe(48))"`）。泄漏=可伪造任意用户 token。默认值仅供本地。 |
| `ALLOWED_ORIGINS` | CORS 允许源（逗号分隔） | 设为真实前端域名（如 `https://play.example.com`）。 |
| `FLASK_DEBUG` | 调试开关 | 生产**不要设**（默认 False）。 |
| `USER_DATA_DIR` | 存档目录 | 指向持久卷；目录权限收敛到服务账号。 |
| `AUTH_CREDENTIALS_PATH` | 凭据文件路径 | 同上，持久卷；与存档一并备份。 |
| `AUTH_TOKEN_MAX_AGE` | token 有效期（秒） | 可选，默认 7 天。 |
| `INVITE_CODE` | 注册邀请码（设了则**注册新号**必须带对码，挡无限建号） | 可选；公网部署建议设。只卡注册，老账号登录不受影响。`deploy/vps-setup.sh` 默认随机生成并在结尾打印。 |

## 路径①：自部署（家用服务器 / VPS）—— 推荐

后端是「带文件柜的数据服务器」，单进程即可承载单人在线版。

1. **依赖**：`pip install -r backend/requirements.txt`（已钉 Flask 2.3.2 / Werkzeug 2.3.8 / itsdangerous 随 Flask）。建议用虚拟环境。
2. **前端构建**：`cd frontend-vue && npm ci && npm run build` → 产物在 `frontend-vue/dist/`，`backend/server.py` 已配置 `static_folder` 指向它（同源托管，无 CORS 问题）。
3. **WSGI 服务器**：不要用 `flask run` / `app.run` 跑生产。用 `waitress`（Windows 友好）或 `gunicorn`（Linux）：
   - Windows：`pip install waitress` → `waitress-serve --port=5001 --call backend.server:app`（或在 `backend/` 下 `waitress-serve --port=5001 server:app`）。
   - Linux：`pip install gunicorn` → `gunicorn -w 2 -b 127.0.0.1:5001 server:app`（在 `backend/` 目录下，因 `server.py` 用 `import auth` 同目录导入）。
4. **反向代理（可选但推荐）**：nginx/Caddy 终止 TLS、转发到 `:5001`，并直接服务 `frontend-vue/dist` 静态资源与 `/data/images`（比 Flask 服务静态更快，呼应 S9 缓存头）。
5. **环境变量**：按上表设置（尤其 `SECRET_KEY`、`ALLOWED_ORIGINS`、持久 `USER_DATA_DIR`/`AUTH_CREDENTIALS_PATH`）。
6. **备份**：定期备份 `data/user_data/` 与 `data/auth/credentials.json`（存档无数据库，就是这些 JSON 文件）。

## 路径②：Vercel serverless（`api/index.py` 已存在）

`api/index.py` 是 serverless 变体，已与 `server.py` 共享 `backend/auth.py` 的鉴权/原子写/版本逻辑。**但有一个硬约束必须先解决才能真上线：**

- ⚠️ **`/tmp` 易失**：`USER_DATA_DIR` 默认 `/tmp/user_data`，凭据默认落本地文件。Vercel 函数实例无状态、随时回收，`/tmp` 不跨实例、不持久 → **存档与凭据会丢**。无状态 token（itsdangerous 签名）本身能跨实例，但凭据与存档落本地文件不行。
- ✅ **解决方向**：把存档与凭据的读写换成外部持久存储——
  - Vercel KV（Redis）/ Vercel Postgres / Upstash：存 `username → {credentials_hash, save_payload, saveVersion}`。
  - 把 `backend/auth.py` 的 `_load_credentials`/`_save_credentials` 与 `api/index.py` 的存档读写抽象成一个存储接口，本地用文件、serverless 用 KV/DB 实现。
- **环境变量**：在 Vercel 项目设置里配 `SECRET_KEY`、`ALLOWED_ORIGINS` 及存储连接串。
- **CORS**：serverless 前端通常与 API 不同源，`ALLOWED_ORIGINS` 必须设为前端部署域名。

> 结论：serverless 路径在「只加固不实施」阶段保持代码一致即可；真要走它，**存储改造是前置工作**（不在 S10 范围）。

## 单人在线版上线清单（对照 S10 加固项）

- [ ] `SECRET_KEY` 已设为高熵随机值（非默认）。
- [ ] `ALLOWED_ORIGINS` 已设为真实前端域名。
- [ ] `FLASK_DEBUG` 未设（debug 关闭）；`grep -rn "debug=True" backend/server.py api/index.py` 零命中。
- [ ] 用 WSGI 服务器（waitress/gunicorn）而非 `app.run` 跑后端。
- [ ] `USER_DATA_DIR` / `AUTH_CREDENTIALS_PATH` 指向持久卷且权限收敛，已纳入备份。
- [ ] 前端 `npm run build` 产物经反向代理或 Flask 同源托管。
- [ ] `pip install -r backend/requirements.txt` 装的是钉版本（Werkzeug 2.3.8）。
- [ ] （serverless 路径额外）存档/凭据已改外部持久存储，不依赖 `/tmp`。
- [ ] 跑 `python backend/test_security.py` 全 PASS 作为部署前自检。
