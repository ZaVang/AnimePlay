## 维护原则

- 未完成事项只进 `FUTURE.md`；完成后提炼到 `HISTORY.md`。
- 不提交 dated audit、评分表、会话记录、`docs/orch` 运行快照或已完成的 Sprint 合同。
- 一次性分析需要追溯时使用 Git 历史，不在当前文档树长期保留副本。
- 文档引用稳定文件或符号名，避免保存会快速漂移的行号、测试数量和快照分数。
