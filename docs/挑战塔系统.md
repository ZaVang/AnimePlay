# 挑战塔 / 小队战斗系统

> 对应页面 `views/SquadBattleView.vue`、`utils/battleCalculator.ts`、`utils/aiSquadGenerator.ts`。
> 这是**独立于"宅理论战"的第二套战斗系统**——宅理论战是卡牌辩论（声望/议题），本系统是角色 HP/属性数值战。两者不共享引擎。

## 玩法概述

玩家组建至多 3 支小队（每队 4 人，从角色收藏中选），挑战"爬塔"：逐层战斗，每层敌人战力与稀有度递增。胜利获得经验与知识点，并解锁下一层。

## 战斗属性

每个角色有 5 项战斗属性（来源：后端 `process_character_data.py` 按稀有度生成 `battle_stats`）：

| 属性 | 含义 |
|---|---|
| HP | 生命值 |
| ATK | 攻击力 |
| DEF | 防御力 |
| SP | 技能强度（增伤） |
| SPD | 速度（连击率） |

## 伤害公式（`battleCalculator.ts`）

```
减伤率   = DEF / (1000 + DEF)
增伤率   = SP  / (1000 + SP)
连击率   = min(SPD / 10, 50)%
单次伤害 = ATK × (1 + 增伤率) × (1 - 减伤率)
         若触发连击再 × 1.3
         最终向下取整，最小为 1
```

- **战力评分**（用于难度匹配）：`floor((ATK×(1+增伤) + HP×(1-减伤)×0.5) × (1 + 连击率×0.3))`
- **模拟战斗**：双方轮流出手（玩家先手），最多 100 回合，先把对方全队打空者胜，同归于尽为平局。

## 养成属性如何影响战斗（`generateBattleStats`）

角色的养成数据会实打实加成战斗属性，这是养成系统与本系统的联动点：

| 来源 | 加成 |
|---|---|
| 体力（strength） | ATK += 体力×0.5；DEF += 体力×0.3 |
| 智力（intelligence） | SP += 智力×0.4 |
| 魅力（charm） | SPD += 魅力×0.3 |
| 体力+魅力 | HP += (体力+魅力)×0.2 |
| 战斗属性强化（养成训练得到的百分比） | 各属性 × (1 + 强化% / 100) |

最终属性 = `基础 battle_stats × (1 + 强化%) + 养成属性加成`。

## 爬塔机制（`generateTowerFloorEnemies`）

- **5 层一个循环**：循环内位置 = `(floor-1) % 5 + 1`，决定敌方稀有度配置：

  | 循环位置 | 敌方 4 人稀有度 |
  |---|---|
  | 第 1 层 | UR · HR · SSR · SR |
  | 第 2 层 | UR · HR · SSR · SSR |
  | 第 3 层 | UR · HR · HR · SSR |
  | 第 4 层 | UR · UR · HR · SSR |
  | 第 5 层 | UR · UR · UR · UR |

- **属性递增**：每跨过一个完整 5 层循环，敌方属性 +5%（`cycleCount × 0.05`）。
- **难度标签**：循环数 0=简单，1–2=中等，3–5=困难，>5=极难。
- 敌方角色优先用真实角色池，不足时用负数 ID 占位生成。

## 奖励（`SquadBattleView.endBattle`）

| 结果 | 玩家经验 | 知识点 | 角色经验 |
|---|---|---|---|
| 胜利 | 50 + 层数×10 + 存活人数×10 | 25 + 层数×5 | 玩家经验的一半，存活 +20，每层 +5 |
| 失败 | 15 + 层数×2 | — | 失败经验的 1/3 |
| 平局 | 按胜利处理 | | |

胜利后自动进入下一层（`completeFloor` + 本地层数 +1）。

## ⚠️ 已知缺陷（截至 2026-06）

1. **进度不持久化（最严重）**：`presetSquads`（小队配置）和 `towerProgress`（爬塔进度）**不在存档协议里**（`userStore.saveStateToServer` 的 payload 不含这两项）。视图层另用 sessionStorage 存了一份层数，导致刷新后"视图层数"与"store 层数"分裂，`completeFloor` 因层数不匹配而 no-op，**历史最高层永远显示 1**。
2. **战斗引擎内嵌在视图**：`SquadBattleView.vue`（985 行）里塞了完整的回合引擎、奖励结算、AI 调度、自动战斗 setTimeout 链。其中 `calculateRoundDamage` 与 `battleCalculator.ts` 的公式逐行重复（视图明明 import 了却重抄）。
3. **经济直改**：`endBattle` 中 `userStore.playerState.knowledgePoints += knowledgeReward` 直接改钱包，绕过 store action，无事务入口。
4. **文案矛盾**：规则区"每日最多挑战10次"与信息面板"无次数限制"并存，代码实际无限制。
5. 当前层数三处双写：`userStore.completeFloor` / 视图本地 ref / sessionStorage。

详见 `项目审计报告-2026-06-12.md` 一.2、三.4。

## 重构方向

把战斗引擎、奖励结算从 `.vue` 抽到独立模块，与 `battleCalculator` 合一；小队与塔进度纳入存档协议；经济走 store action。
