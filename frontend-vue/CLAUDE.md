# CLAUDE.md

This file guides Claude Code (claude.ai/code) when working in the `frontend-vue` package.

## Development Standards

- Keep files focused; aim for under 200–300 lines and split by concern.
  - Reality check: several files badly exceed this (`skills/effects/index.ts` ~1561, `stores/userStore.ts` ~1178, `views/SquadBattleView.vue` ~985). These are known refactor targets, not patterns to copy.
- Use clear file/folder hierarchy by functionality; follow existing structure.
- Use meaningful names; comment non-obvious logic only.
- Mark incomplete features with detailed `TODO` comments — but **do not ship UI that announces an effect the code does not perform** (the current skill system does exactly this; see Known Debt).

## Development Commands

- `npm run dev` — dev server with hot reload (needs backend on :5001; see root README)
- `npm run type-check` — `vue-tsc` type check (currently passes with 0 errors)
- `npm run lint` — ESLint with auto-fix
- `npm run format` — Prettier
- `npm run build` — type-check + production build
- No test runner is installed (`vitest` absent); `*.test.ts` files are orphaned and do not run.

## Architecture

Vue 3 + TypeScript + Pinia + TailwindCSS, built with Vite.

**Startup**: `main.ts` awaits `gameDataStore.fetchGameData()` (master anime/character data from the backend) **before** mounting the app.

**8 feature modules** (routes in `router/index.ts`, all lazy-loaded except Home):

| Route | View | Module | Doc |
|---|---|---|---|
| `/` | HomeView | 主页：玩家状态/观看队列/统计 | — |
| `/gacha` | GachaView | 抽卡 | `docs/抽卡系统.md` |
| `/collections` | CollectionsView | 收藏/卡组 | — |
| `/battle` | BattleView | 宅理论战（卡牌辩论） | `docs/战斗系统.md` |
| `/squad-battle` | SquadBattleView | 挑战塔（小队数值战） | `docs/挑战塔系统.md` |
| `/nurture` | NurtureView | 角色养成 | `docs/角色养成系统.md` |
| `/guess` | GuessView | 猜角色小游戏 | `docs/猜角色游戏.md` |
| `/settings` | SettingsView | 设置/主题 | `docs/主题系统.md` |

**State (Pinia)**:
- `gameDataStore` — master anime/character/skill data (fetched at startup)
- `userStore` — **god object (~1178 lines, 14+ responsibilities)**: session, level/exp, currencies, gacha draw + collection, pity, history, decks, nurture, viewing queue, shop, preset squads, tower progress, save serialization, logs. Prime refactor target.
- `gachaStore` / `battle.ts` (gameStore+playerStore+historyStore) / `theme.ts` / `settings.ts` / `guess.ts`

**Battle engine** (`core/`): `TurnManager` (turn flow), `BattleController` (play/defense/AI orchestration), `BattleEngine` (pure clash math), `RewardCalculator` (result tables). `core/ai/` holds AI strategies.

**Skill system**: 128 UR skills (64 chars × 2) defined in `data/urCharacterSkillsGenerated.ts` (generated by `scripts/generateUrSkills.js` — do not hand-edit; edit `docs/UR角色技能设计.md` then regenerate). Effects dispatched via `runEffect(effectId)` in `skills/effects/index.ts`. Complex interactions use `InteractionSystem` / `PersistentEffectSystem`.

**Data**: master data fetched from `/api/all_animes`, `/api/all_characters`; images served at `/data/images/[type]/[id].jpg`. User saves: `POST /api/user/data` writes the **entire** state as a JSON file per username (no auth — see root README / audit).

## Known Debt (read before non-trivial changes)

The 2026-06 audit (`docs/项目审计报告-2026-06-12.md`) found these — be aware so you don't build on broken ground:

- **core → stores reverse dependencies (14×)** + 3 circular deps: the battle engine can't run headless. Don't add more `@/stores` imports inside `core/` or `skills/`.
- **~78% of skill effect handlers are fake** (112 TODOs): they `addLog`/`addNotification` claiming an effect but do nothing, while still spending TP. Reference real implementation: `牧濑红莉栖_时间理论`.
- **Economy has no transaction entry**: 4 sites do `userStore.playerState.knowledgePoints -=` directly from components. Route currency changes through a store action instead.
- **Save protocol gaps**: `presetSquads` / `towerProgress` are NOT in the save payload → tower progress is lost on refresh.
- **Battle "no result screen"**: `TurnManager.endGame()` is a stub; `gameStore.setWinner` is never called.
- **172 hardcoded `text-white`** (46 files) not wired to theme vars → titles wash out on the light default theme.
- **Dead code**: `stores/counter.ts`, `components/CollectionStats.vue`, `userStore.logout` (unreachable — logout button has no handler), legacy ALL-CAPS skill stubs.
- **Security (backend)**: save endpoint has no auth; `debug=True`. Must fix before any deploy.
